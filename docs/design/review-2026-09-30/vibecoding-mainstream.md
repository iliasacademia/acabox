# Mainstream vibecoding platforms — feature inventory for the Acabox review

**Group:** Lovable · Bolt.new (StackBlitz) · v0 (Vercel) · Replit (Agent 4)
**Researched:** 2026-09-30. Official docs, changelogs and pricing pages were fetched directly; review-site material is marked as such.

## 0. How to read this

- *Interaction* describes what the user does and sees, not the marketing name.
- *As of* is the date on the source (changelog entry, blog post, review) or the fetch date (2026-09-30) for undated doc pages.
- Acabox status (present / partial / absent / unknown) is judged from the repo's `CLAUDE.md` only — no code was audited here.
- §6 states model calls per use for every idea. "0" means it can be built with no added model calls.
- Anything I could not confirm at a primary source is marked **unverified**.

### 1.2 What non-technical users praise / complain about (review sites)

- Trustpilot: **4.2/5, 1,751 reviews** (fetched 2026-09-30). Praise: "It's amazing how easy you get started and no complicated prompts needed" (Sep 25, 2026); "turned ideas from my head into real working projects" (Sep 28, 2026). Complaints: "cloud tokens are running all the time i run out of tokens so fast" (May 6, 2026); runs "in loops" (Sep 28, 2026); ~33% reply rate to negative reviews. https://www.trustpilot.com/review/lovable.dev
- Aggregated review analysis (Jul 14, 2026): #1 complaint across Trustpilot/Reddit/G2 is **unpredictable credit consumption**, with users "charged for the AI's own mistakes"; **Supabase set-up is the barrier** for non-technical builders ("generates the frontend cleanly, then asks you to connect Supabase, configure security policies and debug auth errors"); praised: speed, code quality, GitHub ownership, and the **visual editor adjusting UI without credits**. Quotes: "The biggest drawback I've run into is the credit-based usage model" (G2); "If you do not use your tokens and end the subscription, they are gone" (Trustpilot). https://www.zite.com/blog/lovable-reviews
- Lovable's own answer to the loop complaint is visible in the product: 10 free fixes, credit check-ins, the "fix once or twice, then Plan mode, then revert" guidance, and the Sep 2026 Chat mode.

### 1.3 Notes for Acabox

Lovable is the clearest model of **cost visibility for a long-running agent**: per-message cost on hover, a running tracker, and a threshold pause with Continue/Finish-up. Its history panel (preview, diff, "go to message", revert, bookmarks) and "Revert and resend" are the rollback pattern non-coders actually use. Its desktop app proves local MCP servers are a feature non-technical users are being offered.

### 2.2 What non-technical users praise / complain about

- Trustpilot: **1.6/5, 203 reviews** (fetched 2026-09-30). Praise: "it was so easy to build a website in just a few prompts" (Sep 2026); client sites "done in under an hour" (Aug 2026). Complaints: "Half the time you spend tokens trying to resolve issues their own AI created" (Aug 2026); "consumes way too many tokens way too fast… run out before minimal working app" (Jul 2026); support "over a week" (Jun 2026). https://www.trustpilot.com/review/bolt.new
- Product Hunt / dev.to quotes compiled Jun 14, 2026: "Tokens are generous but consumed when errors occur… I'd estimate 50% of mine were spent on this"; "When you ask Bolt to fix a simple bug, it often rewrites the entire file, breaks your UI/UX, and still fails to fix the problem"; "it is not always clear what a given action will cost"; "It's tough for non-coders." https://superdesign.dev/blog/bolt-review

### 2.3 Notes for Acabox

Bolt's two durable ideas for a non-coder are **"free to try, pay on save" visual edits with batching**, and an explicit, official **"what costs tokens" list** that tells the user which clicks are free. Its weakness — nothing in the UI says what an action will cost before or after — is exactly the complaint that fills its review pages.

## 5. Cross-cutting UX patterns that matter for a non-technical builder

1. **Cost is the #1 complaint on every platform, and it is always the same shape**: "I paid for the AI's own mistake" plus "I could not tell what it would cost". The platforms that survive it show cost *per message* (Lovable: hover; Replit: hover the checkpoint icon), show it *while running* (Lovable's tracker), and **pause at a threshold** (Lovable check-ins at 20 credits; Replit usage limits that block). None shows an estimate *before* a message; Replit decides the price after the fact, which is what The Register and Trustpilot pile onto.
2. **Free fixes for the agent's own errors** is now a product feature, not a refund policy: Lovable (10/day shared with security fixes), v0 (daily free fixes for *unedited* code), Bolt (security audit fixes free). Users ask for exactly this in v0's community thread.
3. **Fix-loop breaking is taught, not just offered**: every vendor's docs say "fix once or twice, then stop clicking": describe precisely with a screenshot, go to Plan mode, revert. The loop guard is social (docs) rather than mechanical — no platform disables the button after N failures.
4. **Rollback that never loses anything**: Lovable (snapshot per change, preview + diff + "go to message", bookmarks), Bolt (timeline, label, preview, free), v0 (restore = new version, linear), Replit (checkpoint of everything incl. chat and DB, opt-in DB restore). All of them separate **code rollback from data rollback** and say so.
5. **Point at the thing**: select-element → chip in the composer (Lovable `S`), batched free visual edits that cost only on save (Bolt), design panel + Apply (v0), deterministic edits straight to source with no credits (Replit), plus draw/arrow/sticky-note annotations the agent reads (Lovable, Replit, v0 annotations). Non-coders cannot name a component; clicking it is the interface.
6. **Plan before build, and keep the plan editable**: Lovable (1 credit, versioned plans, highlight-to-revise with diff), Bolt (Plan button with "Implement this plan"), Replit (task list with Review/Revise/Build here/Build in background). v0 lacks it and its users ask for a "Build vs Query" indicator.
7. **Evidence, not assurance, for self-testing**: screenshots in chat (Lovable, v0), video replay with step navigation (Replit), "Begin take over" when the agent is blocked (Replit).
8. **Long runs need a steering wheel**: follow-ups while working (Lovable), prompt queues (Bolt 20, Lovable reported 50), stop buttons everywhere, and Lovable's "Finish up" (wrap up gracefully, pay only for completed work).
9. **Progress is a collapsible ledger**: activity cards (Lovable), tool-execution cards (v0), checkpoints (Replit), with per-step details on click; thinking summaries are shown but folded.
10. **Templates and remix beat blank prompts**: every platform ships a gallery with Preview + Remix; Lovable adds three design directions before the first build; Bolt adds a prompt library and "Enhance prompt".
11. **Knowledge in two tiers**: always-on instructions (Lovable knowledge, 10k chars) vs on-demand skills with "Save from chat" (Lovable), "Use a skill" (Replit), `/` skills (v0, Bolt). Replit's **Memories** are opt-in, viewable and editable in Settings.
12. **Secrets are requested by name with a reason in the chat, then write-only** (Lovable); pasting a key offers a connector (Lovable); connectors are revocable centrally (Replit). The agent never sees the value.
13. **Publish has a gate and a dot**: a quick security scan before publish (Lovable, Replit), a pending-changes dot on the Publish button (Lovable), explicit "Update" to push (Bolt, v0).
14. **Scheduled work lives in the chat that created it** (Replit Routines) with a per-run budget.
15. **Mobile and collaboration are table stakes for these platforms** (Lovable/v0 apps, Replit/Bolt multiplayer) but irrelevant to a single-user desktop tool.
16. **Desktop clients exist to reach local tools**: Lovable's desktop app is justified entirely by local MCP servers and tabs.
