# Published UX patterns and guidelines for AI agents and vibecoding tools — what they say, and what each would mean in Acabox

Research group: published pattern libraries, platform guidelines, essays and academic HCI, 2023 – September 2026.
Compiled 2026-09-30. Other agents audited Acabox's code; this report judges Acabox only from the repo's CLAUDE.md status log, and says "unknown" where that log is silent.

Method and limits (read first)
- Sources were located with ~30 web searches, then every primary page was fetched directly. The session's shared web-search budget ran out after the first sweep, so later coverage came from fetching pages already identified; the gaps this left are listed in "Caveats" at the end.
- Every claim carries a source URL and an as-of date. "Via search snippet" means the page itself could not be fetched (403/JS-only) and only an excerpt returned by the search engine was seen; treat those as partially verified. Anything I could not confirm is marked unverified rather than guessed.
- "Model calls per use" below counts extra Anthropic API calls a pattern would add in Acabox beyond the chat turn the user already pays for. "0" means the pattern is pure UI/plumbing or rides inside an existing turn (it may add tokens to that turn; where that matters it is said).

Acabox facts used to judge status (all from CLAUDE.md as of 2026-09-28)
- Progress: a running turn shows the current step's name, target and a ticking clock; finished turns fold to "Worked for 4m 12s · 26 steps", failures counted in red, results (tool cards, plan prompts, last task checklist) never fold. Activity page: Needs attention / Running now (Stop, elapsed) / Recently finished. Job registry survives restarts (WORKING, RAN WHILE CLOSED, INTERRUPTED). Status bar: "N TOOLS WORKING", "AGENTS N LIVE". Chat rows: amber pulsing dot = working, blue dot = unread, "Chats • 45" in the rail.
- Oversight: `allowedTools` is auto-approve; there is no `canUseTool` handler, no sandbox, read-only folders are advisory, two PreToolUse hooks (secret reads, host installs). Agent has unrestricted Bash over the workspace.
- Recovery: "Ask Claude to fix it" composes a real build error into a turn; BUILD FAILED and BEING WRITTEN are verified build states, not narration; tool delete keeps data; skills have trash + revert; no user-facing checkpoint/restore of a tool's code.
- Cost: user's own API key; model + effort pinned per chat and shown as a chip ("Opus 5.5 · High"); no token/cost display anywhere; onboarding removed entirely; requires system Python 3.9+ and npm on PATH.
- Prompting: empty-state "Where to?" with profile-seeded chips; attachments, screenshot, dictation, quote-to-composer chips, chat links, model picker; chat search over message prose; tools own many chats.
- Notifications: `show_notification` desktop toast tool for the agent; tool-job notifications deliberately deferred (design in CLAUDE.md: unit = the wait, tiered by where the user is, only for >30 s or failed).

### 2. Jakob Nielsen at UX Tigers (uxtigers.com), 2025–2026

- Think-Time UX: Design to Support Cognitive Latency (Oct 23, 2025) — https://www.uxtigers.com/post/think-time-ux. "Don't make me think faster." Five time windows (perception 0–400 ms, comprehension 0.4–2 s, decision 2–10 s, execution 10–60 s+, recovery minutes+). Concrete: motion affordance within 200 ms; meaningful status text instead of spinners ("Analyzing data"); ETAs with uncertainty bands ("between 1–3 minutes beats false precision"); background long tasks with persistent indicators; deliver partial results progressively; durable job IDs across sessions; on return, "Since you were gone…" recaps and visual diffs of what changed; notifications that lead with the outcome ("Saved", not "Operation completed").
- 2026 AI and UX Predictions: Mid-Year Reality Check (Jul 2, 2026) — https://www.uxtigers.com/post/2026-predictions-halfway. Generative UI adoption lagging (47%) "due to user reliance on spatial stability and muscle memory (Jakob's Law)". Anti-pattern "silent quality downgrading": routing to a cheaper model without saying so is "quality roulette"; proposes "nutrition labels for inference" naming the model and reasoning depth. "The bottleneck to widespread, frictionless AI adoption is the user interface." The first breakout hit made entirely by a non-programmer is still pending.

### 3. Google PAIR — People + AI Guidebook (published May 8, 2019; updated May 18, 2021)

https://pair.withgoogle.com/guidebook-v2/ (structure: 8 guiding questions, 38 patterns; the patterns index page is JS-only and did not fetch — pattern names below come from the chapter pages, which did).

- Mental Models (https://pair.withgoogle.com/chapter/mental-models/): set expectations for adaptation; onboard in stages — "be up-front about what your product can and can't do the first time the user interacts with it"; the one-line template "This is {product}, and it'll help you by {benefits}"; plan for co-learning; disclose the algorithmic nature of conversational UIs.
- Explainability + Trust (https://pair.withgoogle.com/chapter/explainability-trust/): articulate data sources; tie explanations to user actions; account for situational stakes (explain more when the user is "catching a flight"); partial explanations with progressive disclosure; "if it doesn't make an impact on user decision making, consider not showing [confidence]"; "showing more granular confidence can be confusing"; prefer categorical (High/Medium/Low) or n-best alternatives over percentages; "automate more when trust is high, or risk of error is low"; tell users ahead of time there is a recovery plan.
- Feedback + Control (https://pair.withgoogle.com/chapter/feedback-controls/): keep users in control for tasks they enjoy, high-stakes tasks, and tasks needing creative vision; automate what they cannot or do not want to do; "allow users to adjust their prior feedback and reset the system"; keep a manual fallback; be specific about what feedback changes and when.
- Errors + Graceful Failure (https://pair.withgoogle.com/chapter/errors-failing/): three error types (user, system, context); for low confidence "explain why a certain result couldn't be given and provide alternative paths forward"; when failing, return control with "awareness of the situation, what they need to do next"; make "failure safe, boring, and a natural part of the product".

### 4. Microsoft HAX Toolkit (CHI 2019 guidelines; toolkit materials 2023) and Promptions (2025)

The 18 Guidelines for Human-AI Interaction (https://www.microsoft.com/en-us/haxtoolkit/library/), grouped: Initially — G1 make clear what the system can do, G2 make clear how well it can do it, G3 time services based on context, G4 show contextually relevant information, G5 match social norms, G6 mitigate biases. During — G7 efficient invocation, G8 efficient dismissal, G10 scope services when in doubt (disambiguate or degrade gracefully), G12 remember recent interactions. When wrong — G9 support efficient correction, G11 make clear why the system did what it did. Over time — G13 learn from behaviour, G14 update and adapt cautiously, G15 encourage granular feedback, G16 convey the consequences of user actions, G17 provide global controls, G18 notify users about changes. The patterns page (haxtoolkit/patterns) returned 404; no generative-AI-specific update was found on the fetched pages.

Promptions (Microsoft Foundry Labs, research paper May 2025; MIT licence) — https://labs.ai.azure.com/projects/promptions/. An "Option Module" inspects the prompt and history and renders inline radio buttons/checkboxes/toggles that regenerate the response in real time as the user adjusts them. Study: 38 professionals, six tasks; "strong preference for these adaptive controls" over static presets, lower mental workload, higher success. This is the same mechanism NN/G praised in March 2026 (buttons and checkboxes), measured.

### 6. IBM Carbon for AI (guidelines updated Aug 12, 2026; AI label usage updated Sep 30, 2026)

https://carbondesignsystem.com/guidelines/carbon-for-ai/ and https://carbondesignsystem.com/components/ai-label/usage/. Four principles: transparency (label every AI instance), pervasive awareness of AI's scope, integrated explainability shown only when needed, and "don't use the Carbon for AI styling as decoration". The AI label is the single entry point to an explainability popover with four slots — overview, supporting details, artifacts/resources, additional actions — that stays open until dismissed. "Light as metaphor" (glow, gradients) marks AI-produced content. Revert behaviour: when a user overrides AI content "the AI presence styling is removed and the AI label is replaced by a 'revert' action", so the user can toggle AI vs manual. Twelve components carry AI variants (data table, text input, modal, tile…).

### 7. Apple — Human Interface Guidelines: Generative AI, and WWDC25 session 248 (June 2025)

### 8. Anthropic — published guidance and shipped mechanics

- "How we contain Claude across products" (May 25, 2026; McGuinness, Grace, De Jonghe, Eaton, Ribbink) — https://www.anthropic.com/engineering/how-we-contain-claude. Telemetry: "users approved roughly 93% of permission prompts"; approval fatigue makes per-action prompts weak as a standalone defence. Response: OS sandboxes (Seatbelt/bubblewrap: reads allowed, writes inside the workspace, network denied by default) cut prompts by 84%; an auto-mode classifier catches ~83% of problematic actions while blocking ~0.4% of benign ones; Cowork mounts folders read-only, read-write, or read-write-no-delete. Principle: "match isolation strength to the user's capacity for oversight" — technically literate developers get lighter friction, "non-technical knowledge workers require absolute boundaries", and the architecture "defaults toward deterministic environmental controls rather than relying on user judgment".
- Claude Code permission modes (docs fetched Sep 30, 2026) — https://code.claude.com/docs/en/permissions. Modes: default/Manual (ask on first use per tool), acceptEdits, plan (read-only exploration, no edits), auto (classifier reviews shell and network actions), dontAsk (auto-deny), bypassPermissions. Tiered table: reads free inside working dirs; Bash asks except a built-in read-only set; file edits ask until session end; web fetch asks except pre-approved doc domains. "Yes, and don't ask again" saves a rule. A user can attach a comment to a Yes/No answer; a "No" with a reason lets Claude continue with that reason, a bare "No" stops the turn. Permission rules "are enforced by Claude Code, not by the model".
- Plan mode as experienced (claudelog.com, updated Sep 3, 2026, third-party) — https://claudelog.com/mechanics/plan-mode/: Shift+Tab twice or /plan; Claude may only read and write a plan file; the user edits or removes steps; exit asks a confirmation; with newer models the plan phase opens with clarifying questions.
- Latent Space, "Claude Code's Next Era — Thariq Shihipar" (Sep 29, 2026) — https://www.latent.space/p/thariq. AskUserQuestion "was the first time the model was good at elicitation"; artifacts "with a database" so multiple Claudes share state; per-task effort control (low/medium/high/max) changes outcomes a lot in some domains and little in others; "implementation notes" surface considered-but-rejected solutions; power users invest heavily in the initial prompt and run supervisor agents. On non-technical users: a "high skill ceiling" remains; AI-assisted prompt generation and skill composition are the assumed on-ramp. Thariq at Every's Vibe Code Camp (notes undated): have Claude "interview you about requirements for roughly 30 minutes before execution".
- Academic read of Claude Code's design space (Liu et al., arXiv 2604.14228, Apr 14 / Jul 2, 2026): seven permission modes plus classifier, five-layer context compaction, four extension mechanisms (MCP, plugins, skills, hooks); contrasts "per-action safety" (Claude Code) with "perimeter-level access" (OpenClaw).

### 11. Practitioner pattern libraries for agents, 2026

- Roman Kamushken, "16 AI agent UI design patterns" (Sep 21, 2026) — https://www.setproduct.com/blog/ai-agent-ui-design-patterns. Intent: goal-clarification prompt (1–3 scoping questions with prefilled defaults), scope boundary chips (what the agent can access). Plan: editable plan, effort-and-cost preview with optional spending cap, dry-run. Execution: live step ledger (pending/running/done/failed), tool-call cards (input, output, duration), reasoning disclosure collapsed per step. Background: persistent nav indicator with running count that turns amber when input is needed. Checkpoint: tiered permission gates (read grey/no prompt; write blue/ask once; destructive red/ask always), batch approval, interrupt-and-redirect ("pause, not kill"). Result: diff-first summary, confidence-and-gaps statement (Verified / Assumed / Could Not Do). Audit: action trail with per-action undo, handoff to human. Six shipping anti-patterns: infinite spinner, approval fatigue, the confident wrong result ("tests pass" without running them), chat log as audit trail, hidden autonomy (installs dependencies with no ledger entry), fake progress (bar hits 90% then stalls). Decision rule: autonomy by reversibility × error cost.
- Andy Smith / HatchWorks, "Agent UX patterns: chat-first UX fails" (Mar 25, 2026) — https://hatchworks.com/blog/ai-agents/agent-ux-patterns/. Taskboard + outcomes; activity timeline; start/stop/pause/resume; autonomy levels (suggest → draft → execute); two-phase actions ("show the plan first … then execute with a receipt"); action receipts (what changed, where, timestamp, rollback); evidence panel ("citations and data sources rather than chain-of-thought dumps"); human checkpoint gates by type (approve plan / execution / final output / exceptions); safe failure with "I'm stuck" states; memory controls ("what I remember", "why", "edit/delete"); budget and time boxes with a permission request near the limit.
- AI UX Playground (patterns updated Jul 11–13, 2026) — https://aiuxplayground.com/pattern/checkpoints-and-restore/ and https://aiuxplayground.com/pattern/status-steps/. Checkpoints: every agent reply becomes a restorable point; the restore control sits under the reply and says "Restore to this checkpoint"; warn that restoring discards later messages; never checkpoint before irreversible external actions (payments, sends). Progress steps: collapsed by default, specific labels (not "Processing"), timestamps and durations, the trace persists after the answer; examples Perplexity, ChatGPT thought summaries, Claude extended thinking, Cursor tool timelines.
- Zylos Research (May 28, 2026) — https://zylos.ai/research/2026-05-28-agentic-ux-frontend-design-patterns-ai-agents/: high-risk gates, progressive delegation, plan-and-execute previews, step-level intervention, activity-panel separation, resume from checkpoint, "3 of 7 steps complete" roll-ups, three-part errors (what happened / why / what to try), and the claim that binary high/low confidence outperforms percentages (unverified beyond this source).
- inference.sh (Sep 18, 2026) — https://inference.sh/blog/ux-agent-ux-patterns: streaming progress, explicit status, action transparency before consequential actions, controllable autonomy; anti-patterns silent processing, unexplained delays, hidden failures, approval fatigue.
- Fuselab (Sep 8, 2026) — https://fuselabcreative.com/ui-design-for-ai-agents/: separate the conversation from the activity stream because "agents take multiple autonomous actions between user messages"; "silence while the agent works is the fastest path to user anxiety"; cites Gartner (Aug 2025): 40% of enterprise apps will embed task agents by end-2026.
- ParallelHQ (Aug 5, 2026) — https://www.parallelhq.com/blog/ai-ux-best-practices: 15 practices (adjustable autonomy, audit interface, intentional friction, contextual nudges, GenUI, guided prompting, progressive disclosure, graceful degradation, confidence indicators, transparent provenance…). Its onboarding companion cites "68% day-one churn" (attributed to NN/G) and a "Baymard 2026" template study (+45% completion); neither statistic could be traced to a primary source — unverified.
- Tian Pan, "The Magic Moment Problem" (Apr 17, 2026) — https://tianpan.co/blog/2026/04/17/magic-moment-ai-onboarding-converts-skeptics: "a user staring at a blank prompt box has no intuition about what's possible"; tooltips fix "feature exists", not "user can imagine using it"; complete a real task in the first session; "show 3 focused examples instead of 20 options"; measure time-to-first-value; trigger help from behavioural signals (repeated hovering, failed attempts). ## Part 3 — Anti-patterns the literature names, and where Acabox stands

| Anti-pattern | Who names it | Why it matters for a non-technical scientist | Acabox |
|---|---|---|---|
| Infinite spinner / silent processing — minutes behind one dot, no step names, no elapsed time | setproduct (Sep 2026); inference.sh (Sep 2026); Fuselab ("silence … is the fastest path to user anxiety") | Cannot tell slow from hung; will re-prompt and pay twice | Avoided (step name + clock; swallowed-turn fix 2026-09-21) |
| Fake progress — percent bar hits 90% then stalls | setproduct; Nielsen Think-Time (prefer uncertainty bands) | Teaches distrust of every indicator | Avoided (elapsed only) |
| Approval fatigue — a modal per write/command trains reflexive Allow | Anthropic (93%); setproduct; inference.sh; Yan (Aug 2026) | Prompts become theatre; real risks slip through | Avoided by having no prompts — but with no boundaries either (see B4) |
| Hidden autonomy — installs or sends with no ledger entry | setproduct | The user cannot audit what happened to their data | Partially avoided (install wrapper logs; API proxy audit; tool cards) |
| Confident wrong result / "tests pass" without running them | setproduct; Bai et al. (Jun 2026); Ibrahim (Jul 2026) | A wrong number can end up in a paper | Avoided for builds; open for data results (G1–G3) |
| Chat log as audit trail | setproduct | 400 lines of narration is not a record | Partially avoided (fold + Activity) |
| Over-asking / asking what it could infer | ClarEval (Feb 2026); NN/G (plain-text follow-ups skipped) | Each question is a turn of effort for someone who cannot judge the options | N/A until elicitation is rendered; needs a cap |
| Under-asking / assumptive generation ("silent failure") | LHAW; ChatGPT Agent critique (NN/G Aug 2025) | Builds the wrong tool from a vague ask | Open (no scoping step before scaffold) |
| Jargon — secret, key, token, .env, PATH, venv, esbuild, MCP | GeekWire (2026); Stack Overflow blog (Jan 2026); PAIR ("focus on benefits rather than technology terminology") | The audience stops at the first unknown word | Open: API key + Python/npm prerequisites are the front door |
| Generic disclaimers everywhere | NN/G Hallucinations (Feb 2025); NN/G Explainable AI (Dec 2025) | Becomes "background clutter" and is skimmed | Avoided (none) |
| Numeric confidence as reassurance | Whitmore (2026); Li (2025); PAIR | Raises agreement on wrong answers too | Avoided (none) — keep it that way |
| Silent model downgrade / quality roulette | Nielsen mid-year (Jul 2026) | User pays and cannot tell why quality moved | Avoided (resolved model id pinned and shown) |
| Sparkles as the only AI signifier; anthropomorphic personality | NN/G Sparkles (Sep 2024); Humanizing AI is a trap | Inflated trust, unclear affordance | Unknown |
| Re-generating the whole interface each time (GenUI churn) | Nielsen mid-year; NN/G GenUI (2024) | Breaks muscle memory in the user's own tool | Guarded by design system; no explicit "don't relayout" rule |
| Fix-loop that eats credits and context | AppStuck (May 2026); eesel (Jun 2026) | Money and morale burn with nothing to show | Open (no attempt counter, no revert) |

## Part 4 — What Acabox could take from this (prioritised for non-technical scientists building local data tools)

Each item: the pattern, why it fits Acabox's constraints (no mocks, cost, simplify, Claude-only), and extra model calls per use.

1. Mechanical boundaries before any prompting (B4, B3). Enforce read-only folders with a PreToolUse hook; confine writes to workspace + tool-data; prompt only for delete-outside-tool-data, publish, and send. This is Anthropic's own conclusion for "non-technical knowledge workers" and resolves a hazard CLAUDE.md already lists. 0 calls.
2. Restore to this checkpoint (C1, D4, F3). Snapshot `.applications/<dir>` before each writing turn; "Restore" under the turn fold and in the tool menu; count consecutive failed fixes and offer restore + fresh chat after three. Directly answers the most-cited non-technical complaint ("it wiped out an existing feature"; "10–20 reverts"). 0 calls.
3. Real cost on every turn (D1, D3). Usage/cost from the SDK result in the meta line, per-chat total in the header, month-to-date in Settings; soft cap warning. The user pays their own key and today sees nothing; this is the zero-mock version of Lovable's missing feature. 0 calls.
4. Elicitation as buttons, capped (B1, H1). Confirm AskUserQuestion renders as chips/checkboxes in both composers; CLAUDE.md policy: one round of ≤3 questions before scaffolding a tool, never for small edits; Promptions-style option chips for the few analysis decisions that matter. 0 extra calls (same turn).
5. Verified / Assumed / Could-not-do footer and data provenance (G1, G2, G4). Analysis replies end with three honest lines naming their sources; mini-app charts carry "from <file> · N rows · filters" with a "Show the rows" drawer; no numeric confidence, but "unreliable when…" sentences. 0 extra calls (tokens only).
6. "Check this number" on the selection toolbar (G3). Re-derives a selected value by a different method and reports match/mismatch. 1 turn per use, user-initiated; the highest-value model call this audience can buy.
7. Plain-language front door (E3, E4). A dismissible Home card stating what Acabox does and will not do; an API-key sheet that defines the term, tests the key, and names the pinned model's price class; bundle Python to remove the PATH wall. 0 calls (1 tiny key-test call, user-initiated).
8. Zero-cost suggestions that close the imagination gap (E1, E7, E2). Chips derived from the scan's existing knowledge of the folders and from file types; a small gallery of real example tools with their originating prompt. 0 calls (the removed hourly suggestion scan is the version to avoid).
9. Inline result cards before full tools (I2, I4). A table preview or one figure returned inline with a single "Turn into a tool" action; a one-screen sample before scaffolding. 0 extra calls; removes scaffold/build turns for trivial questions.
10. Finish the recorded notification design and add the "while you were away" line (J1, A5). Composed from the job registry and unread chats; outcome-first wording. 0 calls.
11. Lightweight plan display, heavy result review (B2). A six-line brief with Go/Change rather than an editable plan file; invest instead in the result-side gates above, since approved plans still produce wrong code and this audience cannot evaluate plan text. 0 extra calls on Go.
12. Pause-and-steer (B5). Turn Stop into "Pause, add a note, continue" using the live-session message path CLAUDE.md records as working. 0 extra calls.
13. Draft/Final model toggle in the tool panel (D2). 0 extra calls; lowers the cost of existing ones.
14. Memory and context visibility (K2, K3). "What Claude knows here" per tool (global/local/ambient) and a read-only MEMORY.md with line delete. 0 calls.
15. Disclosure exports for papers and shared tools (G7, L2). An "AI-use note" per chat/tool from the DB; a provenance line on published viewers. 0 calls.
16. Stability rule for generated UIs (I3). Skill instruction: change data, keep chrome; never relayout a tool unless asked. 0 calls.
17. Jargon audit of UI copy (anti-pattern table). Replace venv/esbuild/MCP/PATH wording in user-facing states with plain outcomes; keep technical detail behind the Debug tab. 0 calls.

Patterns the evidence argues against adopting
- Numeric confidence scores on results (raises over-reliance; Whitmore 2026, Li 2025, PAIR).
- User-authored permission policies as the main safety control (non-experts do not maintain them; Yan 2026).
- Per-action approval prompts as the default (93% approval; Anthropic 2026).
- Generic disclaimers under every answer (skimmed; NN/G 2025).
- Regenerating a tool's whole interface per request (Jakob's Law; NN/G 2024, Nielsen 2026).
- Model-generated suggestion feeds on a timer (the cost rule; Acabox already removed one).
