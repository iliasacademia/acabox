# Anthropic consumer and prosumer surfaces — feature inventory and what Acabox could take

Research group: Anthropic consumer/prosumer surfaces (Claude.ai web/desktop/mobile, Cowork, Claude Code, Claude Design, Claude in Chrome, computer use, and the one product this review did not expect: **Claude Science**). Research date: 2026-09-30. Scope rule: other products only; Acabox status is judged from the repo's CLAUDE.md, not from reading code.

Legend for every claim: **[verified: official]** = read directly from an Anthropic docs/support/news page; **[verified: third-party]** = read from a non-Anthropic article; **[release notes]** = one line in Anthropic's dated release-notes page, interaction detail not independently fetched; **[unverified]** = seen only in search snippets, could not fetch the page. "As of" is the page's own last-updated date where it printed one, otherwise the fetch date (2026-09-30).

Acabox status vocabulary: present / partial / absent / unknown, judged against CLAUDE.md as of 2026-09-28.

---

## 0. The headline findings

1. **Claude Science (public beta 30 June 2026) is a near-direct competitor to Acabox** and is included in a $20/month Pro plan. It is a desktop app (macOS 13+, Windows 11, Linux) that pairs Claude with a sandboxed local Python/R analysis environment, grants folder access by card, saves every output as a versioned artifact with a five-tab provenance record (Messages / Code / Execution Log / Environment / Review), runs a background **reviewer** that checks Claude's claims against what actually ran, pins **comments to a point on a figure**, shows a **Compute monitor** per kernel, a **Context usage** view, and a credit balance with pause-and-confirm before extra spend. It ships 60+ read-only scientific database connectors with no keys needed, a literature-access chain (OA first, then publisher keys/EZproxy), SSH/Slurm remote jobs, and a Team plan for scientists with free Standard seats for 12 months. Sources: https://claude.com/docs/claude-science/overview.md, /core-concepts.md, /artifacts.md, /the-reviewer.md, /comments.md, /changelog.md [verified: official, 2026-09-30].
2. **Anthropic's own product line has converged on a few UX primitives that Acabox lacks:** scoped permission cards (Once / This conversation / This project / Global), a universal "always ask before permanently deleting", per-turn file checkpoints with rewind, a plan-then-approve gate, cost/usage visibility, "Waiting on you" grouping, and notifications when a session finishes or needs input. Several of these are available to Acabox for free through the Agent SDK it already uses (`enableFileCheckpointing` + `rewindFiles()`, `canUseTool`, `AskUserQuestion`, `total_cost_usd` on every result message). Sources: https://code.claude.com/docs/en/agent-sdk/file-checkpointing.md, /agent-sdk/user-input.md, /agent-sdk/cost-tracking.md [verified: official].
3. **The dominant complaint across every Anthropic agent surface is opacity about usage/cost and how fast agentic work burns it.** Anthropic answered with `/usage` attribution, a usage ring, spend caps, and pause-before-overage. Acabox users pay per token on their own key and currently see nothing. Sources: HN thread https://news.ycombinator.com/item?id=47586176 [verified: third-party, comments ~6 months old]; https://code.claude.com/docs/en/costs.md [verified: official].
4. **The cost model is the structural difference.** Every Anthropic surface is subscription-included (Pro $20, Max $100/$200, Team $20–25 Standard); Claude Science and Claude Code and Cowork and Design all draw on one shared limit, and overage is opt-in "usage credits" at API rates with a monthly cap. Acabox requires the user's own API key and bills at API rates from the first token. Source: https://claude.com/pricing [verified: official, fetched 2026-09-30].

## 1. Plans, pricing and the cost model (context for every feature below)

**Consumer and team plans [verified: official, https://claude.com/pricing, fetched 2026-09-30]**
- Free: $0. Chat on web/desktop/mobile, web search, file creation, code execution, memory, app connections, Artifacts. No Claude Code, no usage credits.
- Pro: "$17 Per month with annual subscription discount ($200 billed up front). $20 if billed monthly." Includes "Claude Code included," "Claude Design, Slides, Docs," "Claude Science," Projects, more models, Chrome/Microsoft 365 extensions. Fable access "requires Usage credits".
- Max: "From $100 Per month", "5x or 20x more usage than Pro", higher output limits, early access, priority at high traffic.
- Team Standard seat: "$20 Per seat / month if billed annually. $25 if billed monthly." Premium seat: "$100 ... $125 if billed monthly", "5x more usage than standard seats".
- Enterprise: "Seat price + usage at API rates".

**Claude Team plan for scientists [verified: official, https://claude.com/programs/team-plan-for-scientists]**
- Eligibility: "Principal investigators (PIs) or equivalent at accredited universities and nonprofit research institutes working in the natural sciences, mathematics, computer science, engineering".
- Standard seats free (regularly $20/mo); Premium $15/mo (regularly $100/mo); 12 months from sign-up; 1–25 seats; includes Claude Science, Code, Cowork, "Connectors to scientific databases and skills", SSO. Verification at `claude.ai/labs-verification/attestation`, 5–7 business days.

**Usage limits and overage [verified: official]**
- All paid plans share a rolling 5-hour window plus a weekly cap, across chat, Code, Cowork, Science, Design. Claude Science: "Your Claude Science usage counts toward the same usage limits as the rest of your Claude plan, including Claude Code and Cowork." (overview.md)
- Usage credits (Pro/Max): Settings > Usage → Enable; payment method; "monthly spending cap" or "Set to unlimited"; "$2,000" daily redemption limit; "billed at standard API rates"; dashboard shows real-time consumption and month-to-date credit cost; "a clear notification when approaching and reaching your included usage limits, with a confirmation that you'll continue with usage credits." https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans (last updated "this week" as of 2026-09-30).
- Claude Science's limit UX is the most explicit: "As you approach one, Claude Science asks whether the session should continue. For the 5-hour limit, you can choose Keep going or hold the session until the limit resets." Without credits and a reset <8h away, "The session pauses, and the composer shows when it will resume"; >8h away it "pauses for up to 8 hours, then stops". "In each of these cases, your conversation and artifacts are kept." (overview.md)

**What users say [verified: third-party]**
- HN (https://news.ycombinator.com/item?id=47586176): "You have no way to know what the real limits are, nor to verify what was actually consumed"; "you can't effectively plan a development session if you aren't sure how far you'll likely get"; "Claude automatically enabled 'extra usage' on my pro account for me (I had it disabled) and the total got to $49 extra before I noticed". Suggestions: real-time token visibility, hard predictable limits, refunds for bug-driven spikes, human support escalation.
- Cowork reviews (9x, 2026-09-28; usecarly, 2026-07-17): usage limits "the single loudest complaint"; agent work "gets through your allowance faster than chat does"; "browser work is still the most expensive thing Cowork can do against your usage allocation".

**Why this matters for Acabox:** a non-technical scientist's cheapest route to "Claude that runs my analysis in my folders" is now a $20 Pro subscription (or a free Team-for-scientists seat) with Claude Science, not an API key. Acabox cannot change its cost model by itself, but it can stop being the only surface in this family that shows the user nothing about spend.

## 3. Claude Cowork (desktop agent for local folders)

Primary sources: https://claude.com/docs/cowork/overview.md, /guide/dispatch.md, /guide/projects.md, /guide/plugins.md, /changelog.md (Aug–Sept 2026 only were present), support articles 13345190 (get started) and 13364135 (use safely), third-party reviews. Cowork launched 2026-01-12 (third-party) and reached GA on macOS/Windows 2026-04-09 (release notes). On 2026-09-16 Cowork's capabilities were folded into every conversation (release notes).

### 3.1 What it is
- "Cowork uses the same agentic architecture that powers Claude Code, accessible within Claude Desktop without opening the terminal... Describe a desired outcome, then return later to completed work." Key capabilities: "Works directly on your computer — Claude reads and writes local files without requiring manual uploads or downloads"; Claude in Chrome pairing; "Sub-agent coordination"; "Professional outputs" (Excel with formulas, PowerPoint, documents). Connectors/skills/plugins managed from **Customize** in the sidebar; "Cowork loads the ones enabled for your claude.ai account, synced at session start, and doesn't read the Claude Code CLI's ~/.claude directory". [verified: official]
- Code runs "in an isolated environment on Anthropic's servers" (get-started article) — earlier third-party pieces describe a local VM sandbox; the current official wording says Anthropic's servers for code/shell. [verified: official]

### 3.2 Permission model (the part Acabox should study)
- Three modes, chosen from a selector: **Manually approve** ("pauses and asks for approval before each action"), **Automatically approve** ("reviews each action for safety before it runs and blocks anything it determines to be unsafe"; note "consumes more of your usage limit than the other modes"), **Skip all approvals** ("nothing checks its actions"). The Cowork tab "shows no mode selector at all until a mode beyond its default is enabled for your account" (permission-modes.md). [verified: official]
- **Hard rule in every mode**: "Cowork requires your explicit permission before permanently deleting any files. You'll see a permission prompt and must select 'Allow'". Guidance: "Consider creating a dedicated working folder for Claude rather than granting broad access, and keep backups of important files"; avoid scheduling "actions that are difficult to undo". [verified: official, 13364135]
- Folder access: a dialog asks whether Claude can read, modify, and delete files in the chosen folder (third-party). 2026-09-04: home folder, Documents, AppData, macOS Library and whole drives can be attached, but "Claude's own configuration and session data inside them stay off-limits, as do certain credential and shell-startup locations (for example SSH keys, AWS and Google Cloud credentials, and bash, zsh and PowerShell profile files)". [verified: official changelog]
- 2026-09-29: an org connector tool set to "Restrict to Ask" "now asks for your approval, including in 'Skip all approvals' mode"; "an ask policy on a file tool shows an approval prompt instead of refusing the call." [verified: official changelog]
- Prompt injection framing: attacks succeed only when "Claude can read information outside your trusted boundary, and can perform actions that could compromise the user." [verified: official]

### 3.3 Progress, results, files
- "progress indicators show what Claude is doing at each step" and users can "jump in to course-correct or provide additional direction mid-task" (get-started). File pane: Office previews (2026-09-29 fix: "the preview now says what failed (workspace not responding, no permission to the folder, file gone)"), "inline playback for video outputs in the file pane, with thumbnails in the chat", Download. Attachments that cannot be read "Claude now marks the attachment with the problem, says what to do, and offers Retry" (2026-09-02). Skill updates from a file card now "apply in one step with an Undo toast instead of a confirmation dialog" (2026-09-02). [verified: official]
- Undo of file edits: no Cowork-wide file rewind is documented; the safety article's only recovery advice is backups. Claude Code's checkpointing (§4.3) is the mechanism in the Code tab. [verified: official, by absence]

### 3.4 Scheduled tasks (Cowork)
- Added 2026-02-25 (release notes): "Recurring and on-demand task scheduling", plus a Customize section. Third-party: type `/schedule` in any Cowork task, "every weekday at 8am". Local tasks run only while the app is open and the computer awake (9x review). 2026-07-07 (buildtolaunch): Cowork scheduled tasks can run on Anthropic's cloud (beta); changelog 2026-09-11 describes "the automatic move of scheduled tasks to the cloud" and "Move to cloud" on a task. [release notes + verified: official changelog + third-party]

### 3.5 Dispatch
- "Dispatch is a long-running agent in Cowork that takes high-level instructions and carries them out in the background... breaks it into tasks, runs each one as a separate Cowork or Code session, and surfaces the results in the sidebar when they finish." Routing table: coding → Code; knowledge work → Cowork project. Task states: Running / Awaiting input / Awaiting answer / Completed / Error / Archived. "When a child task needs permission... the prompt is forwarded to you. If you don't respond within ten minutes, the request is automatically denied and the task continues without that action." From the phone: "Claude messages you the outcome (a spreadsheet, a memo, a comparison table, a pull request) rather than showing you every step of the process"; push notification "when a task is done or when Claude needs your go-ahead"; desktop must stay awake. Pro/Max only, "limited beta". [verified: official, dispatch.md + support 13947068]

### 3.6 Skills and plugins in Cowork
- **Record a Skill (2026-07-21, Pro/Max/Team, desktop only)**: from the + menu, "Record your screen while you do a task, talk through it as you go, and Claude turns it into a skill it can run again" (Claude on X, via search). Third-party: captures screen, clicks, typing, narration (~10 min), emits a SKILL.md; "Video and audio are not retained" claimed by one source while another says Anthropic "has not released detailed privacy or data retention documentation specific to skill recordings" — treat retention as **unverified**. [verified: third-party]
- Plugins: "Installing one can add skills, MCP connectors, subagents, commands, or hooks in a single step"; Customize > Plugins > Discover; marketplaces from GitHub repos; "Installing doesn't add or sign you in to any connector"; limits 200 MB/5,000 files per plugin. Required org plugins can't be removed. [verified: official, plugins.md]

### 3.7 Projects (Cowork)
- A project bundles Description, Folders, Instructions, Links, "Projects from Chat", and "A project-scoped memory store". "Projects live on your computer. They aren't synced to the cloud." Three starts: Start from scratch / Import a project / Use an existing folder. Archiving "deletes its metadata (name, instructions, links, memory). It does not touch the local folders". Changelog 2026-09-11 notes local projects "moving to claude.ai". [verified: official]

### 3.8 What non-technical users praise and complain about
- Praise (9x, 2026-09-28): "does the work"; Skills and Connectors make it "part of how the work actually gets done"; "For most business professionals, Cowork is worth it".
- Complaints (9x; usecarly 2026-07-17): usage limits; desktop-only scheduling; connectors "pull only the first few hundred or thousand rows of a dataset, so for real analysis you're better off exporting to a file first"; "Cowork is designed to be watched" / "closer to a copilot you drive than a colleague"; no inbox; Google Workspace can't send mail; browser work expensive and injection-prone; a learning curve — "Success requires proper briefing and verification rather than casual prompting." [verified: third-party]

## 4. Claude Code (CLI, Desktop app, VS Code, web/cloud, mobile)

Primary sources: https://code.claude.com/docs/en/whats-new (weekly digests W13–W37 2026), /desktop.md, /desktop-quickstart.md, /permission-modes.md, /checkpointing.md, /costs.md, /memory.md, /agent-view.md, /interactive-mode.md, /routines.md, /desktop-scheduled-tasks.md, /artifacts.md, /claude-projects.md, /mobile.md, /computer-use.md, /chrome.md, /goal.md, Agent SDK pages. All [verified: official, fetched 2026-09-30].

### 4.1 The Desktop app for people who do not use a terminal
- Three tabs: "Chat: General conversation with no file access... Cowork: An autonomous background agent... Code: An interactive coding assistant with direct access to your local files. Depending on the permission mode, you approve each change as Claude proposes it or review the changes after Claude makes them." (desktop-quickstart.md)
- First run: pick Local/Cloud/SSH/WSL, "Select folder", choose model, type a task. Review: "Auto or Accept edits: Claude applies its file changes, and an indicator such as +12 -1 appears"; "Manual: Claude proposes each change and waits for your approval... if you reject a change, Claude asks how you'd like to proceed instead."
- Steering: "click the stop button to interrupt immediately, or type a correction and press Enter to send it without stopping the running action. Claude reads the correction as soon as the current action completes."
- Panes: chat, diff, browser, terminal, file, plan, tasks, subagent, iOS Simulator; pop any pane out to its own window (W37). Browser pane opens HTML/PDF/image/video paths from chat and previews dev servers; external sites get classifier review of write actions in every mode.
- Diff view: click `+12 -1`; click a line to comment; "Claude reads your comments and makes the requested changes, which appear as a new diff"; **Review code** button asks Claude to review its own diff.
- Usage ring: "Click the usage ring next to the model picker to see your current context window usage and your plan usage for the period."
- Notifications: "The desktop app sends an OS notification when a Code session finishes a task and you aren't currently viewing that session."
- Side chat (`Cmd+;` / `/btw`): "ask Claude a question that uses your session's context but doesn't add anything back to the main conversation"; not saved to disk.
- Tasks pane shows subagents, background shells, workflows; click to see output or stop.
- Claude can suggest spin-off work "as a task chip in the chat. Click the chip to start that work in a new session with its own worktree".
- Auto-continue after a usage limit (W33): "check Auto-continue when limits reset on the limit card and the app retries the interrupted turn once the limit resets."

### 4.2 Permission modes, plan mode, auto mode
- Modes (desktop table): Manual (`default`) "You see a diff and can accept or reject each change"; Accept edits; Plan ("proposes a plan without editing your source code"); Auto ("a background classifier checks that they align with your request"); Bypass permissions (Pro/Max toggle "Allow bypass permissions mode"). "A mode you pick in the selector is remembered per folder... except Plan, which applies to the current session only." Best practice tip: "Start complex tasks in Plan so Claude maps out an approach before making changes."
- Plan mode approval prompt: "Yes, and use auto mode" / "Yes, manually approve edits" / "No, keep planning"; `Ctrl+G` opens the plan in an editor to edit it; accepting a plan titles the session. 
- Auto mode: "A separate classifier model reviews actions before they run, blocking anything that escalates beyond your request, targets unrecognized infrastructure, or appears driven by hostile content Claude read." Became the default starting mode for new sessions on Pro/Max/Team from 2026-08-14 (W32) and on every plan/provider from v2.1.283. Bash prompts gain "Yes, and switch to auto mode". Auto mode "also nudges Claude to keep working without stopping for clarifying questions".
- "Actions no mode auto-approves" exist (e.g. critical-path `rm -rf`, archiving a session — "You see the approval card in every permission mode, including Auto and Bypass permissions").

### 4.3 Checkpoints and /rewind (undo)
- "Every prompt you send that starts a turn creates a new checkpoint"; snapshots kept for the 100 most recent checkpoints; "Claude Code saves checkpoints with the conversation, so you can still run /rewind after you resume a session"; snapshots swept ~30 days after last save.
- `/rewind` or `Esc Esc` opens a menu listing each prompt; actions: "Restore code and conversation", "Restore conversation", "Restore code", "Summarize from here", "Summarize up to here", "Never mind". Code-restore options appear only when there are tracked edits after that point.
- Limits: "Checkpointing does not track files modified by Bash commands" (`rm`, `mv`, `cp`); subagent edits not restored; external changes not tracked; symlinked/hard-linked paths skipped with a warning; "Not a replacement for version control".
- **Agent SDK equivalent (directly usable by Acabox)**: `enableFileCheckpointing: true` + `extraArgs: { "replay-user-messages": null }` → each user message carries a `uuid`; later `query({ prompt: "", options: { ...opts, resume: sessionId } })` and `rewindQuery.rewindFiles(checkpointId)`. "File rewinding restores files on disk to a previous state. It does not rewind the conversation itself." Tracks Write/Edit/NotebookEdit only; "Creating, moving, or deleting directories is not undone". (agent-sdk/file-checkpointing.md)

### 4.4 Background agents, subagents, agent view, Projects

### 4.5 Memory

Claude saves it to auto memory"; `/doctor prompt-audit` finds stale or conflicting instruction files.

### 4.6 Cost and usage display
- `/usage`: Session block with "Total cost: $0.55", API vs wall duration, lines changed, per-model tokens incl. cache read/write; "Prompt cache (main): 14 requests · 91% of input tokens from cache · 2 misses..."; plan breakdown with **attribution** to skills, subagents, plugins, MCP servers as percentages; **behavior flags** when long context or cache misses account for ≥10%; **loops** rows per scheduled task with per-run tokens; `d`/`w` toggles 24h/7d. - Status line can show cost/duration and context window usage continuously. Background token usage disclosed ("typically under $0.04 per session"); prompt suggestions are skipped when the cache is cold or near a limit.

- **Agent SDK**: every `result` message carries `total_cost_usd`, `usage`, and `modelUsage` (per model, with `costBasis`); in streaming-input mode "total_cost_usd and modelUsage carry the running total for the whole call so far"; `maxBudgetUsd` caps a call; per-step `output_tokens` is a placeholder — read output from the result. ## 5. Claude Science — the closest analog (public beta 2026-06-30)

Primary sources (all [verified: official, fetched 2026-09-30]): https://claude.com/docs/claude-science/overview.md, get-started.md, core-concepts.md, artifacts.md, the-reviewer.md, comments.md, tools-and-environments.md, connectors-and-skills.md, literature-access.md, remote-compute-clusters.md, custom-connectors.md, how-claude-science-works-with-your-data.md, monitor-usage.md, safeguards.md, changelog.md. Reviews: TechCrunch 2026-06-30, Northeastern News 2026-06-30, The Scientist (undated, July 2026), Pebblous report 2026-06-30 [verified: third-party].

### 5.1 What it is and who pays
- "Claude Science is a desktop application that pairs Claude with an analysis environment on your computer... You describe a research task or analysis in plain language; Claude writes and runs Python, R, or shell code in a sandbox, reads the folders you grant it, pulls data from scientific databases through connectors, and saves results as versioned artifacts with a full provenance record. A background reviewer can check Claude's claims against the work that was actually run." "Your files stay on your computer, and code runs in a sandbox. You approve each new folder, network host, and remote job before Claude can use it."
- Honest framing in the docs: "Claude can make mistakes. The reviewer reduces, but doesn't eliminate, errors. It checks claims against the execution record and doesn't re-run analyses... Claude Science is a research tool and isn't intended for clinical or diagnostic use."
- Fields: not only life sciences — "computer science and machine learning, engineering, materials science, mathematics, physics, the social sciences".
- Included in Pro/Max/Team/Enterprise ("nothing separate to buy"); not on Free; macOS 13+ (Apple silicon or Intel), Windows 11 (since 2026-09-10), Linux; ~5 GB disk; sign in with the Claude account — "No API key is required."
- Install: first launch "sets up its runtime and starter Python and R environments, which takes a few minutes, then opens a new tab in your default browser" (macOS/Linux run as a local web app; Windows has its own window). A setup wizard covers connectors/skills, allowed websites, and memory on/off.
- Data: conversation history, artifacts, memory, settings, credentials stay local; Anthropic receives model requests (incl. file contents Claude read), web search queries, dictation audio, feedback, telemetry (no content). Not available: ZDR, BAA coverage, third-party cloud inference.

### 5.2 The core interaction loop
- "Open the Example project, or create a new one. Start a conversation. Reference a folder on your computer by typing its path or using the @ picker in the composer. Review the folder-access card when it appears and choose whether to allow it. Review the code-execution card when Claude proposes running code and choose whether to allow it. Results appear as artifacts in the Files panel."
- **Permission cards** (core-concepts.md): "A permission card appears in the conversation each time Claude needs a new kind of access. The card names exactly what's being requested." Table: Read or write a folder → "Access <folder> on your computer?" (Read-only or Read & write; persists until revoked); Run code → "Run Python code? / Run R code? / Run a shell command? / Install packages?" (Once, This conversation, This project, or Global); Reach a network host → "Connect to <target>?"; Use a connector tool → "Use <tool>?"; Use a saved credential; Run a remote job → "Run this job on <host>?". "All standing grants are listed in Settings > Permissions and can be revoked there." Changelog 2026-09-22: when a cell runs in a folder other than the session workspace, "its permission card now shows that folder". Changelog 2026-09-16: "Saved credentials now reach Claude's code only when it asks for them and you approve. They're no longer present in every cell."
- **Plans**: "Claude might choose to propose a plan before starting multi-step work. You approve the plan or iterate with Claude on refining it; plan text can't be edited directly. Approved plan steps appear in the conversation and are marked complete as work finishes." Changelog 2026-08-07: "When you ask for a plan, Claude now waits for your approval before running code or marking steps done."
- **Sandbox**: "All code Claude writes runs inside an operating-system sandbox on your computer. The sandbox can read and write only the workspace and the folders you've granted. Its network is deny-by-default: outbound connections go through a local proxy that allows only package managers, the scientific databases behind Featured connectors, and hosts you've approved." No root/apt/sudo; builds from source in the sandbox and "saves the build as an artifact for reuse."
- **Delegation**: per-session toggle; "When work splits, a marker appears in the conversation for each track with a status indicator. Click a marker to open that track's transcript. Stop ends the whole session."
- **Composer shortcuts**: "@ inserts an artifact or uploaded file by name; # inserts a past session by title; / inserts a skill."
- Changelog UX details worth copying: 2026-09-22 "Clicking a figure in Claude's answer now opens it beside the chat; Ctrl/Cmd-click or the new 'Open fullscreen' button opens it full screen"; "Opening or closing the right pane now keeps your place in a long answer"; 2026-09-17 "When Claude redraws a figure several times in one turn, the chat keeps only the newest one open; open an earlier step to see its draft"; "Pasted images are now saved to your uploads, so Claude can keep working with them later"; 2026-09-16 "Claude can send you a short message, such as a link to a file, while it keeps working on a task"; "You can comment on and bookmark the short summaries of Claude's progress notes"; 2026-08-27 "Messages now show when they were sent"; "Sessions on Claude Opus 5 now stay focused on what you asked for, with fewer unrequested analyses, figures, and sub-agents"; 2026-07-21 "Annotations travel with your message"; "Edit messages with attachments".

### 5.3 Environments, kernels, compute
- "Python and R run in a persistent kernel that keeps variables in memory across steps in a session. The kernel ends after about 30 minutes idle, when a package install restarts its environment, or when the session ends." Starter envs: Python numpy/pandas/scipy/matplotlib/seaborn/pillow; R tidyverse/ggplot2/jsonlite. Task environments proposed by Claude ("single-cell or structural-biology") via a permission card naming initial packages; shared across projects; inline `pip install` lasts until kernel restart, environment installs are permanent. Sources: micromamba (conda-forge, bioconda...), pip, CRAN/Bioconductor; internal mirrors supported.
- **Compute monitor** (changelog 2026-07-21): "See every running kernel with its memory and CPU use from the new Compute tab. Kernels can be stopped if needed with optional feedback sent to the agent such as 'redo this analysis using less memory'." 2026-07-09: "Claude can now monitor how much memory and processing power its computations are using, and plan its work accordingly."
- **Context usage view** (2026-07-01): "see how full a session's context window is and where tokens go, from the + menu in the composer." 2026-07-21: "Improved context preservation" on Max/Team/Enterprise; sessions moved to a smaller-context model "keep going instead of failing" (2026-09-16).
- Remote compute: SSH hosts from `~/.ssh/config`; probe records CPUs/GPUs/scheduler; Slurm `sbatch` by default; "Run this job on <host>?" card shows command and script; default 30-min job timeout; outputs pulled back, files >~100 MB stay on host. Modal for cloud GPUs (user-billed). GPUs on Linux via Settings > Compute.

### 5.4 Artifacts, versions, provenance, comments, Files
- "In Claude Science, an artifact is a file Claude saves into the project: a figure, processed dataset, report, notebook, or other output... Other files Claude writes during a session are temporary and are cleared a few hours after the session ends; ask Claude to save a scratch file if you want to keep it."
- Files grid is searchable; menu: Pin, Hide, Open in Artifact Viewer, View in context, Provenance, Copy link, Rename, Download, Export Metadata, Export to Cloud, Delete. Previews: HTML zoom/fit-to-width, images to native resolution, Word text previews, "large CSVs show their structure", PDFs first page, Parquet "even for very large files", TSV as tables, 3D structure viewer (PDB, SDF/MOL2/XYZ), LaTeX with cross-references.
- **Versions**: "When Claude saves the same filename again in the same session, the artifact gains a new version." Text artifacts editable in place (Edit content → Save = new version; click a Markdown table cell to edit). "a version stepper and a diff toggle appear. In diff mode, you can choose which earlier version to compare against... Older versions are read-only; to restore one, ask Claude to save it again. Links Claude puts in the conversation point to the specific version that existed at the time."
- **Provenance** (five tabs per version): "Messages: the conversation around the save. Code: a reproducible script, downloadable as a script or notebook. Execution Log: every command that ran. Environment: the environment name, language version, and every installed package with its version. Review: findings from the reviewer." "The Execution Log is the authoritative record of what ran. If the Code tab and the log disagree, trust the log." "Download script"/"Download notebook" zip inputs and outputs.
- **Comments pinned to content**: "Select text in a Markdown, plain-text, LaTeX, or code file; select text in a PDF; click a point on an image or figure; or turn on Comment and click an element in a rendered HTML report." "Saving a comment doesn't send it. Pending comments appear above the message box and are sent with your next message... Claude receives each comment with its filename, the quoted selection (or marked image), and your note." Image comments can "Ask" into a side chat; empty Ask reads "What's going on here?". 1,000-char cap; no threads/resolve.
- Deleting a session keeps artifacts and provenance; deleting a project deletes everything incl. project memory.

### 5.5 The reviewer
- "a built-in verification step that independently re-reads Claude's recent responses, the approved plan, saved artifacts, and the execution record, then checks whether Claude's claims match what actually ran. It runs automatically after responses and periodically during long work, and you can trigger it any time with Request review. Automatic review is on by default on Max, Team, and Enterprise plans; on the Pro plan it starts off."
- Checks: "A result reported as computed when nothing ran. A value in the response that contradicts the file it came from. A citation that doesn't support the claim attributed to it. A reference whose DOI resolves to a different article. An approved plan step that wasn't completed. A conclusion not supported by the method used." It "doesn't re-run analyses" and "doesn't judge whether that method was the right choice".
- Findings UI: "each finding appears as a card directly under the message it refers to, showing what the reviewer found and the finding's status... Click a card to open the reviewer's full reasoning. Claude reads the findings and addresses them in its next message." Users add field-specific criteria in Settings > Specialists > Reviewer. "Reviews run against your plan's usage." TechCrunch's caveat: the fact-checker "uses the same underlying model verifying itself, 'not an independent source of truth.'"

### 5.6 Memory, skills, connectors, literature, safeguards
- Memory: facts stored "in the app's local database on your computer; they aren't synced to Anthropic. The Memory settings page lists every saved fact. You can edit, delete, add, or clear facts there. A per-session toggle... turns memory off for that session only." 2026-07-21: "Search your memories"; "Memories stay in their project."
- Skills: Settings > Skills; **Add skill** via "Chat with Claude, Write from scratch, Upload a skill, or Import from GitHub" (private repos with a token); "You can also ask Claude to distill a workflow from an existing session into a skill." Featured science skills: literature review, indication dossier, AlphaFold2, Boltz-2, Chai-1, ESMFold2, OpenFold3, ProteinMPNN, DiffDock, ESM-2, Evo 2, Borzoi, scGPT, scvi-tools. `/` picker in composer.
- Connectors: Featured connectors "are read-only and don't require an account or key" (16 groups: Genomes, Genes & Ontologies, Variants, Human Genetics, Clinical Genomics, Expression, Regulation, Protein Annotation, Structures & Interactions, RNA, Omics Archives, Cancer Models, Chemistry, Drug Regulatory, Literature Graph (OpenAlex, arXiv), Research Resources (Grants.gov, Antibody Registry) + BioMart, CellGuide, ZINC, Ketcher). "Connector queries appear in the conversation as expandable code steps." When something is not listed: "Ask Claude first. Many public databases and tools work without a connector, because the code Claude runs can reach websites directly. The first time Claude needs a new site, a permission card asks you to allow it." Custom MCP connectors: Remote URL or Local command; "Every tool from a custom connector starts as Not set, and Claude asks before using it"; per-tool Always allow / Ask each time / Block; "Skip approvals" per connector with a warning.
- Literature: "Given a DOI or title, Claude tries in order: an open-access copy (Unpaywall, Semantic Scholar, PubMed Central), CrossRef full-text links, publisher routes you hold keys for, your library proxy, then the publisher page. Retrieved files (PDF, XML, or text) are saved into the session." Credentials: Elsevier, Springer Nature, Semantic Scholar, NCBI, EZproxy URL + cookie; OpenAlex key required. "Paywalled HTML isn't scraped."
- Safeguards: "When a model's safeguards flag a message, Claude Science pauses the session and shows a Chat paused card above the composer. If another model can continue, select Retry with <model>." Optional "Automatically switch models when a message is flagged". Life Sciences Verification Program (Team/Enterprise) with per-session "use case".
- Notifications (2026-08-07): "Get notified when any of your sessions finishes or needs your input, even while you work in another project. In-app notifications are on by default; sound and desktop notifications are under Settings > General > Notifications." Starred/pinned sessions and artifacts; archive projects; per-session reasoning effort.
- Usage: "On Pro and Max plans, see your credit balance and monthly spend limit and turn usage credits on or off under Settings > Usage" (2026-08-07); "Sessions now pause and ask for your confirmation before spending extra usage. Billed usage credits are never drawn on a dismissible warning alone." (2026-07-09); bug fixed 2026-07-08: "idle sessions were consuming usage."

### 5.7 What scientists said
- Praise: Stephen Francis — "Very often it'll get my top three that I'm thinking of, and it'll add a couple more"; Jerome Lecoq — "You have much more information about provenance", built "a multi-agent computational review pipeline" with ~20 custom skills producing "about 10 reviews, many over 100 pages"; Kelvin Lau — "It really shows you step-by-step, 'I am doing this. This is the code I'm using'" and valued local computation for privacy (The Scientist). UCSF: germline glioma analysis "in a sliver of the time... with results independently validated" (TechCrunch).

Pebblous: "Provenance and the reviewer agent do not 'guarantee' reproducibility. They only keep the figure, code, and environment together so you can trace 'what this was made from.'"

## 8. Anthropic's published guidance on agent UX

- **"Measuring AI agent autonomy in practice" (2026-02-18)** https://www.anthropic.com/research/measuring-agent-autonomy [verified: official]: new users (<50 sessions) use full auto-approval ~20% of the time, experienced (~750 sessions) >40%, yet interrupt rates also rise (5% → 9%): users move "from approving individual actions to monitoring and intervening". "effective oversight doesn't require approving every action but being in a position to intervene." 99.9th-percentile turn duration rose from <25 min to >45 min (Oct 2025 → Jan 2026). "Claude Code asks for clarification more than twice as often as humans interrupt it" on the most complex tasks; stops are for presenting alternatives (35%), gathering diagnostics (21%), missing credentials (12%). Recommendations: "trustworthy visibility" and "simple intervention mechanisms"; "agent-initiated stops are an important kind of oversight"; "It's too early to mandate specific interaction patterns"; autonomy is "co-constructed by the model, the user, and the product".
- **"Effective harnesses for long-running agents" (2025-11-26)** [verified: official]: failure modes — context amnesia, "declare the job done" prematurely, undocumented half-finished work. Patterns: initializer writes a feature list (all "failing"), `init.sh`, `claude-progress.txt`, initial commit; each session reads progress + git log, works on "only one feature at a time", tests end-to-end, commits with a summary. Product implication: dashboards showing feature-by-feature progress and clean-state checkpoints for human intervention.
- **"Harness design for long-running application development" (2026-03-24)** [verified: official]: planner / generator / evaluator; "agents tend to respond by confidently praising the work—even when, to a human observer, the quality is obviously mediocre", so evaluation is separated and "tuned... to be skeptical"; sprint contracts define "what 'done' looked like... before any code was written"; "every component in a harness encodes an assumption about what the model can't do on its own".
- Product-level principles visible in the docs: permission cards name exactly what is requested and offer scoped remembering; the delete rule is universal; "green status ≠ task success"; cost of every background helper is disclosed (prompt suggestions, recap, /goal evaluator, auto mode "consumes more of your usage limit"); default modes trend toward auto with classifier review, while non-reversible actions (delete, archive, purchases) stay gated.

## 9. Synthesis — what non-technical users praise and complain about across these surfaces

Praise: "it does the work" in my files; outputs are real files (xlsx with formulas, decks); provenance and step-by-step visibility ("I am doing this. This is the code I'm using"); getting notified and coming back to finished work; skills/connectors becoming part of the routine; being able to control the agent from a phone.

Complaints: (1) usage/cost opacity and speed of burn, surprise overage; (2) "designed to be watched" — still needs supervision, and permission stalls when away; (3) connectors that silently truncate data; (4) desktop-only scheduling tied to an awake machine; (5) over-broad safety refusals for legitimate biology; (6) learning curve — vague prompts fail, briefing and verification needed; (7) export fidelity and co-editing reliability in Design/Docs; (8) platform gaps (Windows/Linux lag).
