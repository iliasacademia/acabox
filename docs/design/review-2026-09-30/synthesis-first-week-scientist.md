# Synthesis — the first week of a non-technical scientist with Acabox

Lens: a scientist who has never opened a terminal installs Acabox v0.1.27 and tries, over seven days, to get one real result from their own folders. Everything below is judged by comprehension (can they read it), trust (does it say what it did, can they undo it, does it ask before destroying), and the moment they would give up. Recommendations that remove confusion outrank ones that add capability. Compiled 2026-09-30.

## 1. The first week, as the reports and the live app describe it

**Day 1 — download, open, first question.** macOS 15 no longer honours right-click → Open for an ad-hoc-signed app; the sheet offers "Move to Trash", and the release page's notes are the version string (onboarding §2.1, `release.mjs:144`). A Keychain prompt appears with no explanation (onboarding §2.2). Home reads "Command desk", the composer says "describe a tool, paste a repo, or ask", the status bar shows CPU/MEM/DISK/`AGENTS 0 LIVE`, and "Debug" sits in the rail for everyone (live-walkthrough L9-27). The first message is refused: "No Anthropic API key configured. Add one in Settings." — plain text, nothing clickable (shell-home L23). Settings has eight sections; the key is the last control on the page, under "Account", below "Rescan workspace", after Connectors, Claude Design, APIs and Sharing (secondary-tabs L149; live-walkthrough L138-140). There is no link to where a key comes from, no mention that it needs a prepaid balance, and no validation: a wrong key says "Saved." and fails on the first turn with the API's raw text (onboarding §2.3, `index.ts:2737-2771`). **Give-up moment #1.**

**Day 2 — folders and files.** "Add folder" is a bare picker; only folders under the home directory are allowed, so an external drive is refused with "Cannot create a workspace in a sensitive directory" (onboarding §2.4, `WorkspaceController.ts:190-196`). The lock labelled "Read only" promises enforcement; nothing enforces it, and the agent is told "direct edits will fail", which is false (agent-capabilities §4, `agentSession.ts:590`). The Files tab shows a folder called `workspace-data` and a footer saying `~/workspace-data SYNCED` (hard-coded); clicking a `.docx` launches Word via the dropped overlay flow; **one click on the row's trash icon permanently deletes a file or whole folder from the real research directory with no dialog and no Trash** (live-walkthrough #5; secondary-tabs §2.3; verified in §7). **Give-up moment #2, if it happens.**

**Day 3 — the first tool.** On a stock Mac the scaffold is `node …/manage_mini_app.mjs` with no Node on the machine and no shim, and nothing ever installs `react`/`react-plotly.js`/`lucide-react` into the npm prefix, so the first build ends in BUILD FAILED with esbuild output and a "Send to chat — let it fix itself" button that cannot (onboarding §2.7; verified in §7). If Node exists, the card appears and BEING WRITTEN behaves well (tools-lifecycle §1.2). Then either the install gate loops FAILED → QUEUED → INSTALLING forever with no exit and the one actionable sentence the code knows is never shown (tools-lifecycle F1/F2; `userActionable` has no consumer, §7), or the tool opens **blank white with the chip saying IDLE** because a render-time crash is dispatched before anyone listens and the host only knows build errors (live fact; tools-lifecycle F8). Meanwhile every boot runs a pip wave that exits 1 silently (live fact). **Give-up moment #3: "where is my tool?"**

**Day 4 — iterating, stopping, finding the answer.** Pressing Stop destroys the session; the model's dying reply ("the sandbox blocks long sleep commands", a hallucinated reason) is shown as a finished turn, and the next message deletes those rows from the database (live fact; chat-experience §2; production-usage §4.2: 237 rows erased on Sep 30). A bad edit to a tool has no undo (tools-lifecycle F3). When a turn ends on a TodoWrite or a build call, the prose answer is inside the fold: "Worked for 3m 40s · 14 steps", a ticked checklist, and no sentence until the fold is opened (chat-experience §1 "the trap in the fold"; CLAUDE.md records a real instance). **Give-up moment #4: "where is my answer?"**

**Day 5 — what did it cost, what did it do.** ≈$2,750 over nine weeks and $100–160 chats are invisible: `agentSession.ts:1328-1332` keeps only `subtype/result/is_error` (production-usage §2; live-walkthrough #3). No list of changed files exists (chat-experience §2). The Knowledge page shows three identical cards "This chat queried spike without consulting the ledger" (live fact). The agent runs `rm -rf` through Bash with no confirmation and no trash (agent-capabilities §4, §11 step 4).

**Day 6 — "tell Claude who I am".** "About you" is empty; the button that would fill it is labelled "Rescan" under "Account", two sections away; pressing it shows "Scanning..." for minutes with no progress, spends one Haiku call per untagged PDF plus one per manuscript writing cards into a table no screen renders, and overwrites anything typed into About-you (secondary-tabs §6.3, §6.8; agent-capabilities §6).

**Day 7 — things she never needed.** "Every 7 days" fires on the 1st, 8th, 15th, 22nd, 29th (live-walkthrough #6, `scheduleCron.ts:26`); a run's chat is not linked from the task. The Servers page explains "Local MCP servers … separate from Connectors". Option+Shift+A, which types Å, opens a half-built Quick Chat window system-wide (onboarding §2.2).

Where Acabox is already right for this person, and must stay so: the composer as the one obvious action; BEING WRITTEN vs BUILD FAILED as verified states; host-owned jobs and the honest Activity copy ("Ran while Acabox was closed — result unknown", "Stopped by you"); the quit dialog; the pinned-model chip's explanation; quotes and screenshots as the user's language (15.6% of production messages quote; 31 screenshots); the share dialog's size table; chat search with snippets; the scheduler's cost sentence.

## 2. Ranked recommendations

Ordering inside each priority is by the day the problem bites. "0 calls" means no Anthropic API call beyond turns the user already sends.

### P0 — fix before anything else (give-up and data-loss moments of week one)

**01 · First-run path on Home** (ux · 0 calls · S)
Problem: the two setup steps everyone must do (key, folder) are reached only through plain text naming Settings and the deepest part of that page; the refusal is not clickable; the empty-state chips assume scripts and BibTeX. Evidence: shell-home L23-26; onboarding §2.2 ("no first-run nudge of any kind", grep); live-walkthrough L19-21. Proposal: when no key, a Home card "Add your Anthropic key to start" that opens Settings scrolled to the key; when no folders, "Add a research folder" opening the picker directly; make the "No Anthropic API key configured" block a button; replace the static chips with one suggested first message derived from the shared folder's file types once a folder exists. All driven by real state and hidden when done — a nudge, not the removed flow. Benefit: day one ends with a working chat instead of a scavenger hunt.

**02 · Verify the key on save, link to the Console, put the key first** (fix-bug · 0 billable · S)
Problem: `auth:setApiKey` saves anything; the verdict arrives on the first turn as a 401 translation or a raw 400 ("credit balance is too low"); no Console link exists anywhere; the key field is the last control in Settings. Evidence: onboarding §2.3 (`ApiKeySettings.tsx:58-89`, `index.ts:2737-2771`, `agentSession.ts:822,1399`; grep for console.anthropic → 0 hits); desktop-agents §16 (Raycast Verify; Anthropic spend-limit error shapes). Proposal: on save, `GET /v1/models` (already implemented in `modelCatalog.ts`, costs no tokens) → "Key works. Your account can use Opus 5.5, Sonnet 5, Haiku 4.5." / "Rejected" / "No billing on this key"; a link to the Console keys page; one sentence that a Claude.ai subscription is not a key and that keys are shown once; move Account to the top of Settings. Benefit: the day-one failure becomes a three-second check with a next step.

**03 · Remove the hidden developer prerequisites for the first tool** (fix-bug · 0 calls · L)
Problem: scaffolding needs `node`, the "already installed" React packages are installed by nobody, and the first build on a stock Mac ends in BUILD FAILED with esbuild text; the dev npm-site's nested React copies produced the blank-tool crash; `python3` is exec'd from PATH at every launch (Apple's CLT stub dialog on a stock Mac is expected, not reproduced). Evidence: onboarding §2.6-2.7 and gaps 1-2; live fact (duplicate React); live-walkthrough #7; verified in §7 (SKILL.md:29, `containerService.ts:113`, no React in `main/`, `AgentInfrastructureController.ts:550`). Proposal: a `node` shim on the subprocess PATH that execs `process.execPath` with `ELECTRON_RUN_AS_NODE=1` (the app already does this for the agent server and authored MCP servers); seed `react`, `react-dom`, `react-plotly.js`, `plotly.js`, `lucide-react` into `npm-site` at provisioning from a prebuilt, hoisted tarball so one React copy exists by construction; never exec `python3` at launch — probe known locations and `xcode-select -p`, defer the real probe to first notebook use, and show `userActionable` in the tool viewer with a python.org link. Benefit: "vibecoding" works on the Mac the scientist actually has.

**04 · A crashed tool says so** (fix-bug · 0 calls until clicked, then 1 user-initiated turn · M)
Problem: the scaffold's ErrorBoundary renders `null`, `ErrorDisplay` subscribes after first commit, and the host tracks only build errors, so a tool that crashes at mount is a blank white pane marked IDLE and nobody is told. Evidence: live fact; live-walkthrough L65-78; tools-lifecycle F8/F9 (`manage_mini_app.mjs:220-222`, `MiniAppViewer.tsx:1137-1143`). Proposal: the ErrorBoundary renders a plain message ("This tool crashed while opening"); the bridge's error capture (already injected) posts `error`/`unhandledrejection` to the host on first load after a build; `MiniAppViewer` shows a CRASHED chip and "Ask me to fix it", which composes the error into the tool's chat and expands a collapsed panel (the build-error path already does this at `:286`); persist it in `tool-build-health.json` so Home shows it too. Benefit: day three's "where is my tool" becomes one click.

**05 · Install failure is a state, not a loop** (fix-bug · 0 calls, 1 on "Ask" · M)
Problem: `ensureAppDeps` rejection → `setTimeout(attempt, 3000)`, the installer re-queues failed packages, rows cycle FAILED → QUEUED → INSTALLING forever; no error text on screen, no skip, no fix path; the one actionable Python/Node sentence is dropped at `packageInstaller.ts:281`; pip stderr is not logged. Evidence: tools-lifecycle F1/F2 (`MiniAppViewer.tsx:826-847`, `packageInstaller.ts:120-151`); live fact (pip wave exits 1 every boot, nothing shown); §7 (no `userActionable` consumer). Proposal: stop the unconditional retry; render FAILED with the real pip/npm line behind Details, buttons Retry · Open anyway (deps are often only needed at Run) · Ask me to fix it; surface `userActionable` verbatim; log stderr. Benefit: a stuck install stops being a dead end.

**06 · Stop keeps the record** (fix-bug/safety · 0 calls · M)
Problem: Stop destroys the session; no `result` row is written; the model's dying words show as a finished turn; the next message's `cleanupOrphanTurnRows` deletes the partial work (237 rows / 4m16s on Sep 30) while it is still on screen; files the agent wrote are on disk but the chat says nothing. Evidence: live fact; chat-experience §2 (`agentSession.ts:1008-1025`, `chatRepository.ts:329-345`; SDK `interrupt()` unused); production-usage §4.2. Proposal: on `chat:stop` write a `{subtype:'stopped'}` result row immediately (so the sweep spares the turn), keep partial rows, and render "Stopped by you · N steps · changed: a.csv, App.tsx"; discard anything the CLI produces after the stop instant rather than showing it; evaluate the SDK's soft `interrupt()` as a second step, measured, not assumed. Benefit: Stop becomes trustworthy — nothing vanishes, nothing hallucinated is shown as fact.

**07 · Files tab delete goes to the Trash with a confirmation** (safety · 0 calls · S)
Problem: the row trash icon and context "Delete" call `filesAPI.deleteFile` → `fsPromises.rm(resolved, {recursive:true})` on paths inside the user's real research folders; no dialog; no Trash. Evidence: live-walkthrough #5; secondary-tabs §2.3(1); verified in §7 (`FilesTab.tsx:368-371, 449-451`; `fileHandlers.ts:323`). Proposal: `shell.trashItem` plus the same confirm pattern Settings already uses for removing a folder. Benefit: a mis-hit cannot destroy a lab folder.

**08 · Agent deletes go to a trash; a confirm card for deletes outside tool-data** (safety · 0 calls · M)
Problem: Bash/Write/Edit are auto-approved, there is no `canUseTool`, no trash, no snapshot; "clean up the old results folder" runs `rm -rf` silently and the fold reads "Ran 2 commands". Every comparable local-file agent gates permanent deletion (Cowork's hard rule after the 11 GB incident; Perplexity, Manus, Copilot). Evidence: agent-capabilities §4, §11 step 4; onboarding §3; desktop-agents §0(1), §17; anthropic-surfaces §8 (93% approval rate → deterministic controls for non-technical users). Proposal: a PreToolUse hook on Bash that rewrites `rm`/destructive `mv`/`shutil.rmtree` on paths inside shared folders into a move to a per-run trash (`newTrashDir`/`moveInto` already exist for skills) with a 7-day sweep and a Restore row on Activity; a single confirm card class — deleting outside `tool-data`, overwriting a non-empty user file — via a minimal `canUseTool` with Allow / Trash instead / Cancel; everything else stays silent. Benefit: answers "what did it do to my files" with "nothing you can't get back".

**09 · Debug out of the rail; Hard Reset behind Advanced with a truthful list** (remove/safety · 0 calls · S)
Problem: a developer console (Logs, Kernels, Telemetry crash buttons, Podman storage rows) is primary navigation for every user, and "Yes, Delete Everything" is two clicks away with a list naming two dead features and omitting `tool-data/`, which it wipes. Evidence: shell-home §3; secondary-tabs §7; onboarding §3 (`ipc/debug.ts:577-580`); copy-jargon #3, #191-194. Proposal: hide the rail entry in packaged builds (`--debug` or Settings → Advanced → "Open diagnostics"); keep "Save a support bundle" and "Back up / restore" as a Help section; Hard Reset behind a typed confirmation that lists what is actually deleted, including saved tool data; delete the Telemetry throw buttons and Podman rows. Benefit: the most dangerous surface stops being one click from the rail.

**10 · Never fold the final answer** (fix-bug · 0 calls · S)
Problem: `finalAnswerStart` is "first part after the LAST tool call" and is `parts.length` when the turn ends on a tool call; the agent is instructed to end with a TodoWrite marking items done, so the prose answer folds behind "Worked for 3m 40s · 14 steps". Evidence: chat-experience §1 (`turnSteps.ts:117-127`, `src/cobuilding/CLAUDE.md:103-105`); CLAUDE.md records "the right answer was inside it". Proposal: compute the boundary as the last non-blank text part when the trailing parts are checklist/outcome tools, or always render the last prose part outside the fold. Benefit: "where is my answer" never happens.

**11 · Plain-language errors with a Details disclosure** (copy/fix-bug · 0 calls · M)
Problem: raw host and SDK text reaches the bubble ("Agent server failed to become healthy within 15s", "Failed to authenticate. API Error: 401", `ECONNREFUSED`, "Check the Debug panel"); `api_retry`/`rate_limit_event` are ignored so retries look like THINKING…; `result.is_error` is stored but never displayed, so Anthropic's own error text reads as Claude speaking; Anthropic's two spend-limit error shapes are passed through raw. Evidence: chat-experience §4 table and gap 5; copy-jargon #47-#50; desktop-agents §16 (`enforced_spend_limit_reached` 429 without retry-after; self-set 400). Proposal: funnel every host/SDK error in main into a headline + next step + collapsed Details ("Acabox's assistant isn't responding. Try again; if it keeps happening, quit and reopen."); map billing/credit, rate limit, overloaded, spend limit, no-key and agent-not-started to one sentence each; render `is_error` results as an error strip; on spend-limit, pause scheduled tasks. Benefit: a day-one failure explains itself instead of sending a scientist to a Debug panel.

### P2 — later

**24 · Scheduler honesty** (fix-bug/cost · 0 calls, saves some · M)

## 4. Deliberately not built (ideas the reports raise that this lens rejects or defers)

- **A full editable plan mode / plan-approval gate.** Lovable/Bolt/Replit ship it, but approved plans still yield wrong code (byteiota/Nadeem), this audience cannot evaluate plan text, and it adds a call per task. A six-line "here's what I'll build" with Go/Change rides the existing turn (agent-ux B2) — do that via 21, not a mode.
- **Automatic retry of failed builds or automatic forwarding of runtime errors.** +1 call per failure; the cost rule calls it a regression unless opt-in. The manual "Ask me to fix it" (04/05) is the week-one answer.
- **Per-action approval prompts as the default.** 93% approval rate (Anthropic); non-experts approve at runtime regardless (Yan 2026). Deterministic boundaries plus a single delete gate (08, 13) instead.
- **A new memory-management UI.** Dia retired memory; Claude's auto-recall is measured not firing here; per-folder instructions beat memory for scientists. Fold the existing page into Settings (17); do not expand it.
- **Model-generated suggestion chips, session recaps, Haiku row summaries, next-prompt suggestions.** Recurring calls; Acabox already removed the hourly suggestion scan for exactly this reason. Deterministic chips from folder contents (01) instead.
- **Three design directions before a tool; "Verify this tool" autonomous QA.** +1 call per tool / one long turn of many tool calls. Not for week one; opt-in at most.
- **Silent cheaper-model routing for small edits (Hex-style).** Conflicts with the pinned default and with "no silent downgrade"; a visible Draft toggle can come later.
- **A host-owned "wait for" primitive for Devin/Hex-style async work.** The production data's biggest pain (≈56 stalled hours), but L–XL, needs its own design, and a first-week scientist is not running Devin sessions. Record it for the next review.
- **Removing Jupyter and the per-tool notebook.** One user's nine weeks show zero kernel use, but that user is a PM doing analytics through Hex; the notebook path is the data-analysis premise of the product. Revisit with more users (see §5).
- **Bundling Python (python-build-standalone).** Right long-term, L effort; the week-one fix is to stop probing `python3` at launch and show the actionable message (03).
- **Subscription sign-in.** Anthropic's policy forbids third-party use of Claude.ai/Pro/Max OAuth; API keys only. Say so in Settings (02).
- **Element-picker / visual editing inside mini-apps, tool drafts/branches, a template gallery of 6–10 verified tools, sharing for non-operators with per-user tokens, jump-to-message from search.** Real gaps, all valuable, none a week-one blocker; several are L.
- **Numeric confidence scores, generic disclaimers under every answer, open-web deep-research mode, in-app browser, keep-alive sessions, multi-provider gateway.** Ruled out by the evidence or by CLAUDE.md's recorded decisions.
