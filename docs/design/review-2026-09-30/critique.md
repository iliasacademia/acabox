## 0. One-paragraph verdict on the review as a whole

The review is unusually well evidenced on *what is on screen and in the code*, and the verifier pass caught real errors in a third of the canonical items. Its weaknesses are the opposite of the usual ones: it never exercised the product's core promise (an analysis, a Run, a real folder) in the running app; it answers "what is wrong" exhaustively but never answers the one strategic question its own research raised ("why would a scientist with a $20 Pro plan use this instead of Claude Science?"); its own number-one finding (56 hours of waiting) has no P0/P1 recommendation that addresses it; and several P0 items are stated as bugs when the verifiers show they are rare, unreachable, or mis-described. The draft's evidence index also points at files that live in a session scratchpad and will not survive the session.

## 1. Areas no report covered, or covered too thinly

### 1A. Product areas

1. **The product's core premise was never exercised live — in this review or in production.** The only live turn was `sleep 9`/`sleep 25`; the only dev tool was crashed before it was reached; the dev workspace had **no shared folders**, so the Files tab, the Drive card, "what's in my folders?" and the agent reading a real research file were never observed. Production shows zero kernel runs, 14/14 untouched notebooks, and a PM's Hex/Devin analytics — not bench science. CLAUDE.md's own "NOT yet tested at runtime" list (a real chat turn against a shared dir; notebook → kernel → Python; `.applications/install pip`) is still entirely open after a review of this size. Consequence: the review can say the *trust surfaces* (C30, C31) are missing; it cannot say whether Acabox produces a correct t-test, a correct figure, or a working Run button on this machine. That is the thing a non-technical scientist actually cares about. No report ran a scientific task and judged the output.

2. **Message actions — copy a reply, edit-and-resend, regenerate.** chat-experience ranks this High #3 ("the largest feature-level gap in the thread itself"); the draft lists it in §2.6; no canonical item exists. For a scientist pasting a paragraph into a manuscript, "copy reply" is the most basic chat affordance there is. Copy is 0 calls, S; edit/regenerate are user-initiated turns. Confirmed absent by grep.

3. **Manuscripts in the Files tab.** secondary-tabs §2.3(2) rates it HIGH: clicking a `.docx` launches Word via the dropped overlay path and then throws (`setDockRightForDocument` is not exposed by preload); without Word, nothing. The canonical list handles this only as a deletion inside C28 §4.4.4 ("replace with open-in-default-app or nothing") — but secondary-tabs §2.2 shows that once the branch is gone, `.docx`/`.pptx`/`.fcs`/`.xls` fall through to the generic viewer and render as **mojibake in a `<pre>`**, and `.ipynb` renders as raw JSON although a `NotebookViewer` exists. Deleting the Word launch makes the most important scientific file type *worse*. secondary-tabs ideas 3 and 4 (an in-app docx viewer, M; route `.ipynb` to the notebook viewer, S) were dropped by every synthesis. Confirmed in `renderer/index.tsx:758-765`.

4. **External drives, NAS and lab mounts cannot be added** (`WorkspaceController.ts:191`, "must be within your home directory"; the sensitive-dir refusal at `:196` uses the verb "create a workspace"). onboarding §2.4 and gap #8 call it MEDIUM; the draft §2.3 records it; no canonical item. For many wet-lab groups the data lives on exactly these mounts; this is a hard wall on day two, not a nicety. onboarding idea 7 (denylist instead of allowlist + `NSRemovableVolumesUsageDescription`, S, 0 calls) was lost in synthesis.

5. **LaTeX / math rendering.** chat-experience §7 and gap #10: `$\alpha$` renders as dollars; `latex.d.ts` declares a module that is not installed. For the stated audience this is table stakes; it appears in no canonical item and is only in C28's "delete `latex.d.ts`" bullet. Confirmed: no math dependency in `package.json`. 0 calls, S.

6. **The distribution front door: download → Gatekeeper → first launch → updater → Keychain.** onboarding §2.1, §2.8 and gaps #3, #9, #10, #20 establish that on macOS 15 an ad-hoc-signed app shows "Move to Trash" (right-click → Open no longer works), the release notes are literally the version string (`release.mjs:144`), the dmg has no README, only the build machine's arch is built, the update window is off-design with no notes/size/"Later", a failed manual update check shows nothing, every update re-prompts Keychain + TCC, and a denied Keychain prompt blanks the stored key ("No API key configured" with a key on disk) and the re-save falls back to plaintext (`secretStore.ts:51-61,74-82`, confirmed). The draft §2.3 lists all of this; **no canonical item addresses any of it**. C05's first-run cards presuppose the user reached the Home screen. The Developer ID question — the one process decision that removes Gatekeeper, the Keychain churn, the TCC re-prompts and `selfUpdater.ts` — appears only in the owner synthesis §8 and nowhere in the deliverable's recommendations or open questions.

7. **Privacy and telemetry.** onboarding §4 and gap #7: zero user-facing words about what leaves the machine (every file the agent reads goes to Anthropic; web search/fetch are on by default), Sentry crash reporting depends on a build-time env var nobody can see, and the bundled CLI's own telemetry has no opt-out set (`DISABLE_TELEMETRY`/`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` absent — confirmed). The canonical list reduces it to "one privacy paragraph on the key card" (C05). Whether v0.1.27 ships crash reporting is an unanswered yes/no the owner can settle in a minute.

8. **The default Electron application menu** (shell-home §5.5, idea 10): View → Reload / Force Reload / Toggle Developer Tools, Help → electronjs.org. A scientist pressing ⌘R mid-turn reloads the renderer; ⌥⌘I opens DevTools. Not in any canonical item. Confirmed: no `setApplicationMenu` in `src/`. 0 calls, S.

9. **Shell basics with no home:** window bounds and open tool tabs are lost on close/reopen (shell-home §8, idea 15); there is no New Chat button or ⌘N (chat-experience §5); there is no help, "report a problem" or support path anywhere except the Debug tab's "Export Logs" (which C09 relocates). 10. **Accessibility — zero coverage.** No report assessed keyboard navigation, screen-reader semantics (Claude Code shipped a screen-reader mode, per anthropic-surfaces §4.7), text scaling, reduced motion, or colour contrast beyond the dataviz palette validation recorded in CLAUDE.md. For a "thorough UX review" this is a hole, and for an older scientist it is not academic.

12. **Performance from the user's seat.** CLAUDE.md measured mini-app memory; no report measured startup time, time-to-first-token, build latency, the 188 MB download, or fan noise during a 40-minute turn. Thin.

13. **The colleague's side of sharing, and the second scientist in the lab.** C23 is entirely publisher-side. Nobody opened a shared tool as a viewer (the only prior check is the 2026-09-16 CLAUDE.md entry), nobody asked how a colleague who likes the tool gets Acabox and the same tool (export/import zips are the only path, and C22 only renames the button), and the 50-viewer Access cap is mentioned once. Thin.

14. **The Connectors catalog is developer tools** (Hex, Sentry, Notion, Linear, GitHub — secondary-tabs §6.4). For scientists this is the cheapest capability add in the whole review and it is not in the list.

15. **Spreadsheet-first helpers.** science-and-data's zero-call items — an on-drop data profile with three templated starter questions (Julius), a deterministic data-quality check on open (Benchling Notebook Check), "freeze this analysis" (Julius stamp) — never reached the canonical list. 16. **A fourth stock-Mac prerequisite that is also a safety hole: `jq`.** Both PreToolUse hooks pipe the tool input into `jq -r` with no fallback (confirmed in `hooks/block-host-installs.sh:23` and `block-secret-reads.sh:29`); `/usr/bin/jq` ships only on macOS 15+. On macOS 13/14 the hooks exit non-zero-but-not-2, i.e. **the install guard and the secret-read guard are silently inert**. Found by the C04 verifier; in no report, and not in C04's problem statement. It belongs in C04 and in C14.

17. **A latent runaway-spend defect in the scheduler.** validateInterval allows 1–31 days (`scheduleCron.ts:92-93`, confirmed); the C24 verifier measured that `0 0 */25 * *` and `*/31` produce delays above Node's 2,147,483,647 ms setTimeout ceiling, which Node clamps to 1 ms, so the run fires immediately, `scheduleNext` recomputes the same far date and fires again — a loop of full Opus-high turns until quit. With zero production tasks it is latent, but it is the one genuinely unbounded bill in the product today, and no report found it.

18. **Every shared folder is read-only by default** (`workspaceRepository.ts:63` `readOnly = true`, both callers omit the argument — confirmed). No report noticed. It changes C14's shape completely: enforcing the lock as it stands would refuse "fix the typos in my manuscript" for every folder a scientist shares until they find an unlabelled padlock. Decide the default (or make the lock explain itself) before enforcing anything.

### 1B. Competitor landscape

1. **The strategic question was raised and never answered.** anthropic-surfaces §1 states it plainly: "a non-technical scientist's cheapest route to 'Claude that runs my analysis in my folders' is now a $20 Pro subscription (or a free Team-for-scientists seat) with Claude Science, not an API key." Production shows the owner spending ≈$300/month on the API key. Nobody put those two numbers side by side, and none of the three syntheses, the canonical list, or the draft's open questions asks "what is Acabox for, now that Claude Science exists?" The honest answers in the material (local-first with no cloud dependency; mini-apps as shareable artefacts; a credential proxy; a product that cannot be shut down under the user as Opal/Mocha/Relay were) are scattered across §1 and §3.4 of the draft but never assembled into a positioning statement. This is the single largest omission for the owner.

2. **Claude Desktop + a filesystem MCP server** — the zero-build way for a Pro-plan scientist to have Claude read local folders — is not evaluated anywhere; the anthropic report covers Cowork and Claude Science but not the plain desktop app with connectors, which is the more likely incumbent on a scientist's Mac today.

3. **No competitor was used hands-on** (stated in the draft). The direct competitor was never installed. Several load-bearing claims rest on third-party summaries and are flagged unverified by their own authors (Lovable's 50-prompt queue, Base44 prices, Claude in Chrome GA date, Cowork's sandbox location). Acceptable for an inventory; the final review should not present these as observed behaviour.

4. **Spreadsheet-native AI** (Excel Copilot; Gemini in Sheets gets one paragraph in openai-google §10) is the tool a bench scientist most likely already has open; coverage is thin.

5. **Cost comparison across models of use** was never done: own-key Acabox (observed ≈$300/month for a heavy user; a $100–160 single chat) vs Pro $20 vs Team-for-scientists free seats vs Julius $20–45 vs Hex $36–75/editor. The reports hold every number; no table compares them.

## 2. Contradictions — between reports, with the live facts, and between the canonical list and its verdicts

Resolved ones are marked ✓ with the resolution; the rest need a decision in the final text.

1. **Waiting is the #1 finding and has no P0/P1 fix.** The draft's executive summary #1 ("the real-world pain is waiting, not building") and month-three's top-five (56 stalled hours) sit against a canonical list where the only mechanism is the second half of C24 (P1 M) with the deterministic `wait_for` primitive explicitly deferred to "an L follow-on if nudges persist", and §4.5 "deliberately not recommended" (keep-alive). C20 (notifications) does not address it — the C20 verifier shows that in every incident the agent had already ended its turn with a promise, so a finish notification would never have fired. The review says one thing matters most and recommends nothing first about it. It must either demote the finding (it is one PM's Devin/Hex workload, not evidently a bench scientist's — the syntheses say so and the executive summary does not) or put the bounded host-side `wait_for` decision in front of the owner as the first open question.

2. **Stop: code reading vs live observation.** chat-experience §2 and the C01 verifier both read `destroy()` as severing the SSE synchronously, so the post-Stop reply "should never have been written" — yet the LIVE FACT shows a hallucinated reply rendered as a finished turn. The ingress is unknown (grace-period `broadcastSSE` racing the socket close, or a renderer re-subscribe on `sessions:changed`). C01(a)'s "drop anything the CLI emits after the stop instant" therefore has no identified place to put the guard. Must be measured before the ticket is written; the draft states the fix as if the mechanism were understood.

3. **Fold trap: inference vs production.** chat-experience §1 infers that turns "naturally" end on a TodoWrite and hides the prose; C08 hardens that to "the agent is instructed to end with a TodoWrite" (`src/cobuilding/CLAUDE.md:103-105` says "mark items completed when you finish", not that). The C08 verifier measured 305 production turns: **0** had prose hidden behind a trailing TodoWrite/build/TaskUpdate; 2 ended on a tool call (both `ScheduleWakeup`); the live walkthrough showed the fold working ("Worked for 13s · 1 step" above the answer); the CLAUDE.md "right answer was inside it" instance predates the fold and produced no prose at all. C08 is a P0 fix-bug for a defect that did not occur in nine weeks.

4. **Reactions: "armed on any legacy install" vs no build ever had the switch.** C11 says the 96-turns-a-day loop is armed on legacy installs; the verifier traced the only UI setter to the 2026-05-20 slim commit, before Acabox's first version bump, and found the flag absent in both channels. The cost framing is wrong; the dead-code and dead-end-view framing is right.

5. **"Three identical cards"** (LIVE FACT wording via the walkthrough) vs the C27 verifier: three *different* chats with the same auto-title, all naming `spike`, a hosted server the code now excludes — stale pre-fix rows, not duplicates. "Dedupe" is a misdiagnosis; a one-off purge is the fix.

6. **Unlisted tools run vs are denied.** `agentAllowedTools.ts:12-16` and CLAUDE.md's 2026-07-28 measurement say run; production and the live test say denied. ✓ Denied on SDK 0.3.280; the comment is stale. But C18 then conflates mechanisms: AskUserQuestion's one production failure was `Answer questions?` (is_error) and today the CLI tells the model it has no such tool; "NotebookEdit 100%" is 2 denials out of 5 failures; two of the six "haven't granted it yet" rows are **path** asks for Edit/Write into the skills store (a policy a relay must answer) and two are pre-fix WebFetch.

7. **Cost in transcripts.** production-usage says `total_cost_usd` "is not written by this SDK build"; three other reports say every result carries it. ✓ Both true (transcript files vs the SSE result message). One lead nobody followed: `review/out/transcripts.txt` counts **142 `cost-state` lines** in the CLI transcripts — if those carry cumulative cost, historical per-chat spend may be recoverable without the migration C07 proposes. Unverified.

8. **HEALTHY vs STARTING.** shell-home: stays HEALTHY after the supervisor gives up (startedFlag set unconditionally); copy-audit #6: STARTING forever when `running` is false. ✓ shell-home is right; copy-audit's framing is wrong; C10 uses the right one. ## 3. What the final review must say first (the findings that change next week)

1. **Three trust breaks are verified live and each has a zero-model-call fix the size of one ticket — ship them this week.** Stop erases the partial turn at the next message and shows a hallucinated reply as finished (C01a: write the `stopped` result row from `destroy()`, repurpose `cleanupOrphanTurnRows` to append a terminal row instead of deleting — and measure where the post-Stop reply enters before guarding it); a crashed tool is a blank pane marked IDLE (C02 cut A+B: the two-line esbuild `--alias:react` fix, an icon-free crash card in the *synced* `error-capture.ts`/`ErrorDisplay.tsx`, a `CRASHED` chip); Files-tab delete is `rm -rf` on real research folders with no dialog (C03: a separate `files:trashFile` IPC with a confirm, and delete the hover icon on shared-folder roots). Everything else in P0 is smaller than these three.

2. **Cost: the SDK hands over the number on every turn and the app throws it away; ≈$2,750 in nine weeks (~$300/month for one heavy user) was invisible, with 40 of the last 73 sessions at `max` effort.** One S ticket (C07 slice 1, JSON field, no migration). Say in the same breath what no report said: at list price the pinned default (Opus 5, $5/$25) costs 25% more per token than the current Opus (5.5, $4/$20, same tokenizer), so the recorded "don't move the default on cost grounds" rationale now cuts the other way — coupled with the fact that all 23 silent fallbacks and both hard refusals in production were on Opus 5.5 chats, so a default change needs C15's fallback rendering first. Owner decision, stated as one.

3. **Positioning: Claude Science (public beta 2026-06-30) is included in a $20/month Pro plan and does, on a scientist's own Mac, most of what this review keeps finding missing** — folder permission cards, plan approval, versioned outputs with a five-tab provenance record, a reviewer, figure-pinned comments, a compute monitor, 60+ keyless scientific connectors. The review documents all of it and never asks "why Acabox?". The defensible answer exists in the material and must be written down: local-first with no cloud sandbox or hosted dependency (Opal, Mocha and Relay all shut down in 2026), mini-apps as shareable instruments, a credential proxy, chat-to-chat links, and the user's own API account. If the owner cannot write that paragraph, the rest of the roadmap is premature.

4. **The review's own #1 finding (≈56 hours of waiting) has no recommendation that addresses it.** Notifications would not have fired (the agent had already stopped); the scheduler has 0 users; the only honest mechanism — a bounded host-side `wait_for` (0 model calls while waiting, exactly one turn when the condition fires, no session kept alive) — is parked as "an L follow-on if nudges persist". Either demote the finding (it is one PM's Devin/Hex workload; a bench scientist's long work is already covered by host jobs) or make the bounded primitive the first open question for the owner. Also fix the one real unbounded-spend defect in the same area: a scheduled interval of 25–31 days overflows `setTimeout` and fires in a tight loop of Opus-high turns until quit (latent; zero tasks exist; confirmed ceiling of 31 days in `validateInterval`).

5. **Vibecoding on a stock Mac is inferred, not reproduced — test it before committing an L.** The code path is solid (no `node`, no npm, React packages installed by nobody, `python3` probed at launch, `jq` required by both safety hooks and absent before macOS 15 — which also means **the install guard and the secret-read guard are inert on macOS 13/14**), but the Apple dialog is expected, not observed, and the Gatekeeper "Move to Trash" sheet on macOS 15 stands in front of all of it with release notes that are the version string. A one-hour fresh-user-account test settles C04's scope; the two-line esbuild alias fix (the dev crash cause) needs no test at all. The whole download→first-launch→update path has findings and zero recommendations; the Developer ID is the process decision behind most of it.

6. **The agent has no brakes, read-only is a lie — and every shared folder is read-only by default.** `readOnly = true` is the repository default with both callers omitting the argument; no report noticed. Enforcing the padlock as the lists propose (C14) would refuse the first "fix my manuscript" request for every folder a scientist shares. Decide the default or make the lock explain itself; then ship the two hooks; the confirm card depends on C18 (L). The fallback "relabel it 'Ask before editing'" is itself a mock (nothing asks).

7. **The data-analysis premise has no evidence either way.** No kernel ran in production or in this review; no scientific task was run end to end; the only live tool was crashed; the dev workspace had no shared folders. Before investing in provenance footers and assumption checklists (C30, C31 — whose honest reach is near zero today because nothing records a run), run three real bench tasks (a CSV → t-test with a figure; a plate-reader export → QC; a FASTQ-folder question) and judge the output and the Run button. That measurement is cheaper than any P1 ticket and may reorder all of them.

8. **A week of deletions and copy is free and large, but three of the "removals" are design reversals.** Debug out of the rail, the Reactions vertical (dead code and a dead-end view — not a live 96-turns-a-day cost, which no build could arm), ~11k unreachable lines, `SYNCED`/`AGENTS 0 LIVE`/`CS:`, the ~40 must-fix strings: all zero-call and mechanical. But Knowledge leaving the rail contradicts a design document marked "Settled", the hardware stats were specified in the Home handoff, and "Running on this Mac" inside Settings runs against `mcp-hosting.md`'s direction and creates a fourth home until C29. Present those three as decisions, not cleanup; and before the owner reads the P0 table, demote C08 (0 of 305 turns) and reword C11, C06, C07, C20, C23 per §4 below so that the list does not open with claims the verifiers have already disproved.
