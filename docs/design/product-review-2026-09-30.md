# Acabox product review — functionality, UX and capabilities against other chatbot and vibecoding platforms

**Date:** 2026-09-30 · **Build reviewed:** v0.1.27 (`main`, clean) · **Status:** review and recommendations; no code was changed. Revised after an adversarial verification pass and a completeness critique (both archived beside this file; see Appendix A).

**Audience the review judges for:** a non-technical scientist who can describe what they want, cannot read code, never opens a terminal, and cannot debug a build. Every finding below is weighed against that person, and every recommendation states its model calls per use (owner's cost-vs-UX rule), whether it is a removal (simplify rule), and whether it shows only real state (no-mocks rule).

---

## How this review was done

Four sources of evidence were combined, and each claim below says which one it rests on.

1. **The code, read by eight independent readers**, one per subsystem (shell and Home; chat; tool lifecycle; Files/Knowledge/Servers/Activity/Settings/Debug; agent capabilities and guidance; first run, prerequisites, updates and privacy; a copy-and-jargon audit of every user-visible string; and a production-data miner). Each report cites `file:line`. The reports are archived in `docs/design/review-2026-09-30/`.
2. **The running app**, driven over the Chrome DevTools Protocol against `npm start` on the dev channel: every tab, every Settings section, the tool viewer, the share dialog, the scheduler editor, chat search, the model picker, one real Haiku turn, a Stop mid-turn, and a request for the agent's `AskUserQuestion` tool. Screenshots were taken of each screen and read; twelve of the fifty-one are archived. The only tool in the dev workspace was instrumented from inside its iframe to find out why it rendered blank.
3. **The owner's production data, read-only**: the 56-chat database (25,895 rows), the SDK transcripts (235 MB), five days of logs, the 6,665-entry command log, the job registry, every tool manifest, `scheduling.db`, and the skills state. Cost figures are estimated from transcript token counts at list prices; the app itself stores no cost.
4. **The market, researched on the web by seven researchers** (Anthropic's surfaces incl. Claude Science; OpenAI and Google; Lovable/Bolt/v0/Replit; the long tail of no-code builders and the pro agentic tools; AI assistants for scientists; desktop agents on local files and BYO-key onboarding; published agent-UX pattern libraries). Every claim they make carries a source URL and an as-of date in their reports. Web-search budgets ran out partway, so some items rest on official docs fetched directly rather than broad search, and several load-bearing claims are flagged unverified by their own authors.

A synthesis pass (three independent lenses, a merge to 36 items, one adversarial code-check per item, and a completeness critic) produced section 4. The verifiers corrected about a third of the items; those corrections are applied below, and the verdicts are archived.

What was **not** done, and what it means:

- **No scientific task was run end to end in the live app.** The dev workspace had no shared folders, so the Files tab, the Drive card and the agent reading a real research file were never observed; the only live turn was a `sleep`; the only dev tool was crashed before it was reached. Production shows zero kernel runs and a product manager's Hex/Devin analytics workload, not bench science. **This review can say which trust surfaces are missing; it cannot say whether Acabox produces a correct t-test, a correct figure or a working Run button.** CLAUDE.md's own "NOT yet tested at runtime" list (a real turn against a shared dir; notebook → kernel → Python; `.applications/install pip`) is still open.
- No packaged build was tested and no fresh-machine install was run (the stock-Mac findings are from code plus documented macOS behaviour, and are labelled "expected" where nobody observed them).
- No competitor was used hands-on; the direct competitor was never installed.
- Not covered at all: accessibility (keyboard navigation, screen readers, text scaling, contrast beyond the chart palette), localization (dictation and all copy are en-US), performance from the user's seat (startup time, time to first token, build latency, fan noise), and the colleague's side of sharing.

## Executive summary — the findings that change what to do next week

1. **Three trust breaks are verified live and each has a zero-model-call fix the size of one ticket.** Pressing Stop destroys the session, the model keeps talking for two seconds and blames a sandbox that does not exist, the UI shows that as a finished turn, and the next message deletes those rows from the database (production: three Stops in five days, 237 rows and four minutes of work erased on one). A tool that crashes at render time is a blank pane marked IDLE. The Files tab deletes a research folder in one click with no confirmation, recursively and permanently. Everything else in P0 is smaller than these three.
2. **Cost is invisible while being the owner's first rule, and the default model is now the dearer one.** The SDK reports `total_cost_usd` on every result; the host persists `subtype/result/is_error` and discards it. Estimated spend ≈ $2,750 in nine weeks (~$300/month for one heavy user), single chats of $100–160, 40 of the last 73 sessions at `max` effort, no number anywhere in the app. Two things nobody had put side by side: at list price the pinned default Opus 5 ($5/$25 per MTok) costs 25% more per token than Opus 5.5 ($4/$20, same tokenizer), so the recorded "do not move the default on cost grounds" rationale now cuts the other way — but all 23 silent model fallbacks and both hard refusals in production happened in Opus 5.5 chats, so moving the default needs the fallback rendering (C15) first. Owner decision. Separately, the CLI transcripts hold 142 `cost-state` lines carrying `totalCostUSD`; if they are cumulative, nine weeks of real per-chat cost is already on disk.
3. **Positioning: the direct competitor is included in a $20 Pro plan.** Claude Science (public beta 2026-06-30) runs on a scientist's own Mac and ships most of what this review keeps finding missing: folder permission cards, plan approval, versioned outputs with a provenance record, a reviewer, figure-pinned comments, a compute monitor, 60+ keyless scientific connectors. The defensible answer exists in the material — local-first with no cloud sandbox or hosted dependency (Opal, Mocha and Relay all shut down in 2026), mini-apps as shareable instruments that live on disk, a credential proxy the agent cannot see through, chat-to-chat links, the user's own API account — and it needs writing down before the roadmap below is funded (section 3.1, question 1).
4. **The real-world pain in production is waiting, and it has no fix in this list — deliberately framed, not forgotten.** The agent promised to "report back" and never could; the user typed nineteen nudges; eight incidents add up to ~56 stalled hours, four over ten hours. Every mechanism the agent reached for (28 `ScheduleWakeup`, 41 background commands, 4 `Monitor`, 4 blocked `sleep`) dies with the turn. But this is one product manager's Devin/Hex workload: the work it waited on ran elsewhere. A bench scientist's long work (a kernel or script job) is already covered by host-owned jobs. A finish notification would not have helped (the agent had already ended its turn). The only honest mechanism — a bounded, host-side `wait_for` with zero model calls while waiting and exactly one turn when the condition fires — is put to the owner as question 4 rather than built. In the same area, one latent **unbounded bill**: a scheduled interval of 25–31 days overflows `setTimeout`, fires immediately and re-arms in a tight loop of Opus-high turns until quit (C46; zero tasks exist today).
5. **Vibecoding on a stock Mac is inferred, not reproduced — test it before committing the L ticket.** The scaffold is a `node` script, the "already installed" React packages are installed by `npm`, and neither ships with macOS or Acabox; the first build on a fresh Mac ends in a red BUILD FAILED quoting esbuild. Launching runs `python3` from PATH, which on a Mac without the Command Line Tools is Apple's stub (the installer dialog is expected, not observed). Both PreToolUse safety hooks pipe through `jq`, which ships only on macOS 15+, so **the install guard and the secret-read guard are silently inert on macOS 13 and 14**. In front of all of it, on macOS 15 an unsigned app shows "Move to Trash" (right-click → Open no longer works), with release notes that are literally the version string. A one-hour test in a fresh user account settles the scope; the Developer ID is the process decision behind most of the download-to-update path.
6. **The agent runs with no brakes, read-only is a lie, and every shared folder is read-only by default.** Bash/Write/Edit are auto-approved, there is no permission handler, the UI shows a lock and the agent is told "direct edits will fail" while nothing enforces it, there is no trash for agent deletes, and no history to restore a tool from. What no report noticed: `readOnly = true` is the repository default and both callers omit the argument, so enforcing the lock as it stands would refuse "fix the typos in my manuscript" for every folder a scientist shares. Decide the default or make the lock explain itself; then ship the hooks.
7. **The data-analysis premise has no evidence either way.** No kernel ran in production or in this review; every scaffolded notebook is the untouched two-cell scaffold (the notebook *file* works as each tool's state store; the kernel never ran); the one tool with a refresh path has been broken since July. Before investing in provenance footers and assumption checklists (C30, C31), run three real bench tasks and judge the output. That measurement is cheaper than any P1 ticket and may reorder all of them.
8. **The agent cannot ask a structured question, and approval-gated tools fail.** With no `canUseTool` handler every unlisted tool is denied; verified live, the agent says it has no `AskUserQuestion` tool; `NotebookEdit` was denied in production; two of the six "haven't granted it yet" rows were path asks for Edit/Write into the skills store, which the skills design says should work. The agent asks back in prose in 12.8% of turns and the answer costs a whole extra round trip.
9. **The product speaks two languages and names two agents.** The chat and the Tools page speak as a colleague ("Tools I've built for you"); everything around them speaks as a build server (`Servers`, `Knowledge`, `Debug` in the rail for everyone; `CPU 12% · AGENTS 0 LIVE · UP 2H`; `~/workspace-data SYNCED` with SYNCED hard-coded; "paste a repo", "scaffolds", `pid 41823 · node index.mjs`, "frontmatter", "roster"). The UI says "Claude" in about 45 strings, the chat list prefixes replies with `CS:` (the abandoned Coscientist brand), and the agent is instructed to deny being Claude. Several design promises are false on screen: ⌘K only switches to the Chats tab; `HEALTHY` reflects a boot flag; Home's relative times are off by the UTC offset; "Pinned tools" are merely recent.
10. **A week of deletions and copy is free and large, but three of the "removals" are design reversals.** Roughly 10,000 lines of unreachable renderer UI plus 2,600 in a prebuilt app ship (calendar, briefings home, paper monitor, reactions, container tests, a Quick Chat window with stubbed context on a global hotkey that hijacks typing `Å`), plus a Podman-era CPU watchdog emitting ~140 false warnings a week, plus the Reactions system task — dead code with a reachable dead-end view, not the live cost an earlier draft claimed (no shipped build could ever arm it). Knowledge leaving the rail contradicts a design document marked "Settled", the status bar's hardware stats were specified in the Home handoff, and "Running on this Mac" inside Settings runs against `mcp-hosting.md`'s direction. Those three are presented as decisions, not cleanup (section 4.4b).

The good news is structural: most of the fixes are zero-model-call plumbing or copy, several are SDK features already available (`enableFileCheckpointing`/`rewindFiles`, `canUseTool`, `total_cost_usd`, `maxBudgetUsd`, `interrupt()`, `Settings.permissions.deny`), and the parts of Acabox that competitors lack — local files as first-class inputs, durable tool data, host-owned jobs with honest state, quotes with provenance, chat links, the credential-holding proxy — are real and working.

## 1. What works and should be protected

Confirmed by code, by the live walkthrough, and (where marked) by production data.

- **The composer is unmistakably how everything starts.** Home, the chat empty state and the dashed "Build a new tool" card all route to it.
- **Turn folding.** A finished turn collapses to `Worked for 13s · 1 step`; a running step shows its name and a ticking clock; failures are counted in red. Verified live, and verified against production: in 305 completed turns the fold never hid a prose answer (section 2.6). Base44 shipped the same layout a month before Acabox did; both are right.
- **Honest state words.** `Ran while Acabox was closed — result unknown`, `Stopped by you`, `Nothing running, and nothing waiting on you`, the quit dialog ("This work will keep running in the background…"), the scheduler's cost sentence, the API Test verdicts that refuse to invent a pass, the share dialog's size table ("Everything in the table is uploaded"), the share viewer's own line "Shared from Acabox · read-only snapshot · published <date>". This is the voice the rest of the product should adopt.
- **Status that is true or absent.** Idle tools show no chip; `BEING WRITTEN` vs `BUILD FAILED` are measured states; amber/blue chat dots are consistent across six surfaces; the per-chat model pin explains itself; `SHARED · BEHIND` on the Tools page and tool header is computed from real hashes.
- **Input affordances scientists use.** In production, quotes ride on 15.6% of all user messages and 31 images were attached (18 pastes, 13 screenshots) — pointing at things with a picture or an excerpt is how this user reports bugs. Dictation works. Chat-to-chat links work.
- **Durable data and host-owned work.** Deleting a tool keeps its `tool-data`; jobs survive restarts with `WORKING` / `RAN WHILE CLOSED` / `INTERRUPTED`; the Stop button in the tool header kills a real process tree.
- **The chat↔tool link and the per-tool chat switcher** (eight chats on one tool in production) — iteration lives next to the thing being iterated.
- **Security engineering.** Secrets encrypted at rest and masked over IPC; the credential proxy relayed 6,139 third-party calls in one evening with zero leaks; the secret-read hook stopped 31 attempts (where `jq` exists — section 2.3); hosted MCP servers start disabled; imported skills arrive disabled.
- **The knowledge loop fires.** 134 `record_finding` calls across 11 skills in production — CLAUDE.md's "not verified whether the model volunteers it" is stale; it does.
- **The swallowed-turn ladder works in production** ("keeping the turn open" ×2, each followed by the CLI's own answer).
- **Local-first is a selling point the market just proved.** Google's Opal (hosted mini-apps) shuts down 2026-11-17 with no migration path; ChatGPT's data-analysis sandbox resets mid-analysis and loses files; Latch's agent sessions are amnesiac. An Acabox tool is files on the user's disk.
- **The APIs catalog is the one Settings list written for scientists** (NCBI, UniProt, Ensembl, Europe PMC, Crossref, Zenodo, OSF, protocols.io…), ten entries needing no key.
- **Build reliability is high now:** 50/55 agent builds and 65/67 esbuild runs succeeded in production; the failures were all in the first week.

## 2. Findings

Severity is for the target user. "Verified live" means observed in the running dev app today; "production" means read from the owner's data; otherwise the finding is from code reading with the cited location.

### 2.1 Where the hours go: asynchronous work has no honest model (production)

- Turn durations: median 1m43s, p90 ~16 minutes, 44 turns over ten minutes, 13 over thirty, the longest 1h57m (one user message, 1,152 tool calls). Total agent time 27.8 hours across 305 turns.
- Nineteen pure nudges. Before almost every one, the agent had promised to come back by itself ("The poller and heartbeat will bring me back…", "You do not need to do anything. I will report back when it is in."). Gaps of 730, 699, 658 and 656 minutes. Two of the four eleven-hour waits were then swallowed by the resume bug (fixed 2026-09-21), so the nudge itself came back empty and was typed twice.
- Since the 2026-09-21 guidance change the agent says the honest thing ("Nothing is still running on my side. Ask me again in a few minutes"), but the nudges continue because the work (Devin sessions, Hex batch cells, labelling jobs) really takes 5–60 minutes, and the only offered mechanism — a scheduled task on the Activity page — has never been used: `scheduling.db` holds 0 tasks and 0 runs.
- **Scope caveat:** the work being waited on ran on other services. A scientist's long local job (kernel or script) is already a host-owned job with a surviving state. The finding is real for this user and unproven for the target user.
- 149 assistant rows explain what Acabox cannot do. "The agent explaining platform limits" is a recurring genre of reply.

### 2.2 Stop, lost turns and the record of what happened (verified live + production)

- `chat:stop` → `unregisterSession` → `session.destroy()` → `POST /stop` → `queryInstance.close()` (`main/index.ts:2397-2402`, `agentSession.ts:1008-1025`). No result row is written. The next message's `cleanupOrphanTurnRows` (`agentSession.ts:485-491`, `chatRepository.ts:329-345`) deletes every assistant and tool row after the last result. Verified live: 4 rows deleted; production: 237 rows (4m16s) on Sep 30, 27 on Sep 29. Files the partial turn wrote stay on disk with nothing in the chat saying so. The SDK's soft `interrupt()` is never called (four `close()` sites, zero `interrupt()`).
- During the kill grace period the model produced a reply blaming "the sandbox" — a hallucinated reason — and the UI rendered it as a completed turn with `Worked · 1 step · 1 FAILED` (no duration, because no result row). **The ingress of that reply is unmeasured:** code reading says `destroy()` severs the SSE synchronously, so it should never have reached the renderer; it did. Candidates are a grace-period broadcast racing the socket close, or a renderer re-subscribe on `sessions:changed`. Measure before guarding (C01).
- 21 of 326 user messages (6.4%) have no reply row: 3 Stops, ~6 bursts/re-sends, ~12 genuinely lost (mostly pre-fix), including two first messages of new chats and one 12.5-minute silent wait.
- Model fallbacks are unsurfaced: 15 `model_refusal_fallback` events / 23 `fallback` blocks in 6 chats routed Opus 5.5 to Opus 4.8 or Opus 5 while the header chip still said Opus 5.5; two hard refusals ("can't help with this. Start a new session") dead-ended the chat; 10 context compactions happened silently. The renderer has no case for a `fallback` block.
- API retries and overloads are invisible: the CLI's `api_retry` is read only for 401/403, so the user sees `THINKING…` for the whole retry window, and an exhausted retry arrives as ordinary Acabox prose. (`rate_limit_event` is defined for claude.ai subscription users and will not fire on an API key.)

### 2.3 First run on a stock Mac (code; onboarding reader; nothing here was reproduced)

- **Node.js is a hidden prerequisite for the core feature.** The scaffold is `node …/manage_mini_app.mjs`; nothing in `main/` installs react/react-dom/react-plotly.js/lucide-react; they reach the shared prefix only via `npm install -g`, which throws `npm is not installed…` when npm is absent. `nodeSetup.ts:9` says "We don't bundle npm itself — most users on macOS have it via Homebrew, nvm". The first build on a fresh Mac fails with `Could not resolve "react"`. esbuild is bundled; node is not.
- **The `python3` probe runs at every launch** (`AgentInfrastructureController.ts:550` → `pythonSetup.ts:60-85`). On a Mac without the Command Line Tools, `/usr/bin/python3` is Apple's stub; the code's own comments assume it merely exits non-zero, Apple's documented behaviour is the developer-tools installer dialog. **Expected, not observed.** The `userActionable` message exists (`pythonSetup.ts:159`) and has no consumer. CLAUDE.md records the eager venv bootstrap as deliberate (the install wrapper needs a pip), so the fix is guarding the probe, not deferring the bootstrap.
- **`jq` is a fourth prerequisite and a safety hole.** `hooks/block-host-installs.sh:23` and `hooks/block-secret-reads.sh:29` pipe the tool input into `jq -r` with no fallback. `/usr/bin/jq` ships only on macOS 15+; on 13 and 14 both hooks fail without producing the deny exit code, so the install guard and the secret-read guard are silently inert.
- **Gatekeeper guidance is stale.** The release notes and CLAUDE.md say "right-click → Open"; on macOS 15+ an unsigned, unnotarized app shows "Apple could not verify…" with `Done` / `Move to Trash` and requires System Settings → Privacy & Security → Open Anyway. The release carries no notes (`release.mjs:144` passes the version string), the dmg has no README, only arm64 is built with no label for Intel users.
- **The API key.** First refusal: "No Anthropic API key configured. Add one in Settings." with no link (it reaches the thread as a stream error rendered verbatim). The field is the last control on an eight-section Settings page, under "Account", below "Rescan workspace"; the folder picker is in the first section but as a low-contrast ghost button. No link to the Anthropic Console, no mention of billing or that a Claude.ai subscription is not a key (Anthropic's Feb 2026 policy forbids third-party apps using subscription OAuth, so a key is the only route), no validation verdict on save (an OpenAI key says `Saved.` — although the host already fires `GET /v1/models` with the new key and discards the result, `main/index.ts:2760`), and non-401 API errors ("credit balance is too low") pass through raw. `auth:getApiKey` returns the full plaintext key to the renderer, unlike every other secret.
- **No first-run state** of any kind; `SetupBanner` only renders on an error and still carries Podman stage strings.
- **Folders** must be under the home directory (`WorkspaceController.ts:191`, "Workspace directory must be within your home directory."): external SSDs, NAS and lab mounts cannot be added, which for many wet-lab groups is where the data lives. The sensitive-directory refusal at `:196` uses the wrong verb ("Cannot create a workspace…"). The read-only lock has no explanation and is advisory. macOS folder-access prompts fire mid-turn from child processes with the reason "to manage workspace files", and re-fire after every update because grants are keyed to the ad-hoc signature.
- **Updates**: an off-design 400×200 window with no notes, size or "Later"; a failed manual check shows nothing; every update re-triggers the Keychain prompt and TCC prompts; a denied Keychain prompt makes `decrypt` return `''` so the stored key reads as missing, and a re-save falls back to plaintext with a warning (`secretStore.ts:51-82`; mechanism read, not run).
- **The default Electron application menu ships**: View → Reload / Force Reload / Toggle Developer Tools, Help → electronjs.org. ⌘R mid-turn reloads the renderer. No `setApplicationMenu` anywhere in `src/`. Window bounds and open tool tabs are not restored on relaunch; there is no New Chat button or ⌘N; there is no help or "report a problem" path outside the Debug tab.
- **Privacy is undocumented in-product**: nothing says what goes to Anthropic (every file the agent reads), that web search/fetch are on by default, whether crash reports ship (Sentry depends on a build-time env var nobody can see), or what the bundled CLI sends (`DISABLE_TELEMETRY` / `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` are set nowhere). The only privacy copy in the product is the two microphone/speech permission strings. Four landscape reports name the local-first trust statement as Acabox's differentiator; the product never makes it.

### 2.4 Safety and recoverability (code; verified where marked)

- No `canUseTool` handler; `allowedTools` auto-approves Bash/Write/Edit/WebFetch…; `permissionMode` never set. `rm -rf` on a shared folder runs silently. The agent's rules contain no instruction to confirm before deleting or overwriting user files; the only hooks block package installs and credential reads (and only where `jq` exists).
- Read-only is advisory, the UI shows a padlock labelled "Read only", and the prompt tells the agent "direct edits will fail" (`agentSession.ts:591`) while the acabox skill tells it "Nothing enforces it" (`SKILL.md:271`). **Every shared folder is read-only by default:** `workspaceRepository.ts:63` declares `readOnly = true` and both callers (`WorkspaceController.ts:120,169`) omit the argument. No report noticed; it changes the shape of any enforcement.
- No trash, no pre-edit snapshot, no undo, no diff of what the agent changed in a user file; `workspace-file-backups/` covers only settings and hooks.
- **Files tab Delete** (code; not exercised live): row trash icon and context "Delete" → `fsPromises.rm(resolved, { recursive: true })` with no confirmation (`FilesTab.tsx:368-371,449-451`; `fileHandlers.ts:323`). The hover-revealed icon sits beside Rename on every row including depth-0 shared-folder roots — the catastrophic mis-click. Removing a folder from the workspace *list* does confirm; skills go to a 30-day trash; research files do not.
- The agent can rewrite its own rules: workspace `CLAUDE.md` is provisioned `keep-local`, `SOUL.md`, memory and skills are agent-writable.
- No `maxTurns` or `maxBudgetUsd` on chat or scheduled runs (only the scanner has them).
- Anthropic's own containment data: 93% of permission prompts are approved, so per-action prompts are weak alone; their conclusion is that "non-technical knowledge workers require absolute boundaries" — deterministic environmental controls (deny deletes, enforce read-only) over user judgment. Cowork's universal rule: explicit permission before any permanent delete.

### 2.5 The tool loop (verified live + production + code)

- **A crashed tool is a blank pane marked IDLE** (verified live). The scaffold's `ErrorBoundary` renders `null` and the host (`MiniAppViewer`) tracks build errors only, so a render-time crash has no state, no chip and no fix path. The mechanism is narrower than first drafted: `error-capture.ts` does buffer errors in `window.__cobuildErrors` and `ErrorDisplay` replays them on mount, so the blank *overlay* is best explained by `ErrorDisplay` itself crashing — it imports `lucide-react`, and the dev crash was a duplicate React (`useContext` of null in `useLucideContext`; the dev npm-site holds nested React copies under `lucide-react` and `react-plotly.js`, production's does not). The cause is dev-only and two esbuild `--alias` flags remove it; the failure mode is general. The in-iframe Fix button does not expand a collapsed chat panel (`MiniAppViewer.tsx:1137-1143`).
- **Install failures loop**: `ensureAppDeps` rejects → unconditional 3 s retry (`MiniAppViewer.tsx:836-840`) → the installer re-queues any non-installed package (`packageInstaller.ts:142-146`) → rows cycle `FAILED → QUEUED → INSTALLING…` with no Skip, no error text, no "Ask me to fix it". pip's stderr is captured and then discarded by `handleLine`; only the message and exit code are logged. The wave re-runs on every boot regardless of outcome (readiness is in-memory). In dev the boot wave logged exit 1 with every package satisfied yet still marked the tool ready in 0.75 s, so the live boot did not loop: the loop needs a package pip's output never names, which any pinned spec (`pandas>=2.0`) guarantees, because `readAppDeps` uses the raw requirement line as the identity while `parsePipLine` stops at `<>=!~`.
- **No version history, undo or restore** for a tool: no git, no snapshot, delete is `rm`. After a bad edit the only recourse is to ask Claude to "put it back" from memory. Every platform in section 3 has a restore point.
- **No way to point at an element.** The selection shim quotes text only; a chart, button or slider cannot be clicked and described. Screenshots (31 in production) are the workaround.
- **Runtime errors are forwarded by the user as stack traces** ("An error occurred in mini-app `x`… Stack trace: …"), 15 times in production, in bursts (four Fix clicks in 1.9 s, each a queued model turn); five chats are titled after their error ("React Hooks Called in Wrong Order"); one tool needed 309 edits.
- **The reuse thesis, tested**: 14 tools; opened on a later day than created: 8; opened after their chats went quiet: 3; re-run as a host-brokered job (measurable only since 2026-07-28): 3 ever; 7 published, all within minutes–hours of being built, all with input data included; every notebook an untouched 2-cell scaffold with 0 outputs (the notebook *file* is each tool's working state store — that half works); no tool's source calls `executeCode`; the kernel gateway is absent from 75,000 log lines. Tools either ship baked data or call Python through `exec`. One tool polls a Python script every 5 s while open (2,737 spawns in two days), filling the 300-entry job registry (300/300 entries are that tool's sub-second jobs) and evicting every other tool's history, because the bridge exposes no file-change event.
- **Half-built tools are invisible, not stuck visible**: `dataBrokerOptOuts` has no `App.tsx` since a 35-minute single-message chat; its Home card reads `OPENED 2D` (the scaffold stamps `lastOpened`) and only the viewer shows BEING WRITTEN. `creation_pending` is the analytics "never opened" flag, not a half-built marker. `findForApp` still mints an empty tool-titled chat when a tool with no linked chat is opened; two such rows exist.
- **Outputs**: `OutputFileList`'s Download is a silent no-op for everything except plain text — CSV/TSV, Markdown, XLSX, PDF, images and anything over 10 MB (`OutputFileList.tsx:58-61` downloads only `type === 'text'`), so the skill's own example `results.csv` cannot be downloaded; `downloadFile` takes a string, so no PNG/XLSX export from React; the Plotly modebar (and its camera) is disabled; no print/PDF; no rename/description/icon edit in the UI; no "About this tool"; `tool-data` holds 1.7 GB with no in-app view of size. "Export for a colleague" already exists as `miniApps:export` (zips the whole dir, dereferenced).
- **Stale agent guidance** still leads with the R kernel (`SKILL.md:45,275,442-450`) and ships the `differentialExpression` template that "builds but fails on first Run"; the acabox skill tells the agent it can run R and DESeq2 (`:78,82-85`) and promises a daily activity summary (`:257`); it says tools are "not shareable except as an exported zip" (`:270`), stale since v0.1.14.
- **Non-HTTP data has no credential home**: 38 failures of "No Redshift credentials. Write them to …/input/redshift.json" and 14 Hex 403s — the API registry is HTTP-only, so the agent's fallback was a plaintext JSON in the agent-writable workspace (never created).

### 2.6 The chat (code; verified where marked)

- **The fold is correct in practice.** `finalAnswerStart` is "the first part after the last tool call" (`turnSteps.ts:122-127`), so a turn that *ends* on a tool call would fold its prose. Measured on 305 completed production turns: zero hid a prose answer; the two that ended on a tool call were both `ScheduleWakeup`, with no prose after them. The agent is told to mark tasks completed, not to end with a `TodoWrite`. A three-line rule ("the last non-blank text part never folds") covers the only real shape (C08, P2). What is genuinely missing is a line saying which files the turn changed.
- **No message actions**: no copy-reply, edit-and-resend, regenerate, branch, feedback (no `ActionBarPrimitive`, `BranchPicker` or `EditComposer` anywhere). For a scientist pasting a paragraph into a manuscript, copy-reply is the most basic affordance there is. Code blocks have Copy; the quote toolbar fills the composer, not the clipboard.
- **Tool rows speak shell**: `bash sleep 9` on the running line (verified live), `glob`/`grep`/`fetch`, `EXIT 1`, raw stdout in a `<pre>`; the model's plain-English `description` is used only when the command is empty (`tool-card-display.ts:48`).
- **Clarifying questions are prose only** and the turn ends; the structured tool is unavailable (verified live). Plan mode is invisible: the `EnterPlanMode` card renders `args.plan`, which the CLI never sends; `ExitPlanMode` is auto-approved, so the agent approves its own plan. `approval-buttons.tsx` is a text pattern-matcher with no handler behind it.
- **Attachments**: oversize files fail silently (`attachmentAdapter.ts:204-208` throws; the library's dropzone and paste handlers catch and `console.error`) — in production a 32.6 MB file vanished and cost a 39-minute detour (DB-derived); files dragged from an already-shared folder are copied into the workspace root because the native path never matches the symlink (`:221-229`); the main chat view has no dropzone because `index.tsx:1357` renders `<Thread hideComposer />` and the dropzone is tied to the composer, although the empty state says "drop files"; sent images are never viewable again (only name and size are persisted).
- **Rendering**: no LaTeX (`latex.d.ts` declares a module that is not installed; no `remark-math`/`rehype-katex` in `package.json`; `$\alpha$` renders as dollars); no inline images (`![plot](output/plot.png)` breaks — react-markdown's default `urlTransform` strips `local-file:`; CSP already allows it); a Markdown link to a local path silently does nothing; replies starting with `<` take a Word-overlay-era HTML path.
- **Timestamps are likely wrong beyond Home.** `messages.created_at` has the same zone-less SQLite default as sessions, and `historyMessageConverter.ts:94,169` parses it bare — so bubble times and day separators are very likely off by the UTC offset too (code; verify live, fix with C10).
- **Errors**: raw `ECONNREFUSED`, "Agent server failed to become healthy within 15s", "Failed to authenticate. API Error: 401" reach the bubble; "Agent failed to start. Check the Debug panel for details." sends a scientist to Debug; a mid-turn agent-server crash can end a reply with no message at all (`/events` 404 resolves as a clean end); `result.is_error` is persisted and never rendered.
- **No overall turn clock, no finish notification** unless the agent itself calls the notification tool; a reply that lands while the user is elsewhere gets only the unread dot.
- **Model picker**: Fable/Opus/Sonnet/Haiku with version numbers; "premium cost" is the only price signal; "uses your limits faster" is a claude.ai concept (this product bills per token). Default is the second-most expensive tier (and dearer per token than Opus 5.5 — section 2.7); production runs 55% of recent sessions at max effort.
- **Chats list**: `CS:` prefix; row date is `createdAt` while the list sorts by activity ("1 week ago" on the top row); no pin, folders, archive, bulk delete or export; a search hit opens the chat at the bottom, not at the match; Files has no empty state (Chats does); no New Chat button or ⌘N.
- **Header**: `NAMES ITSELF AFTER THE FIRST REPLY` stays after the title has arrived until navigation (verified live); `GENERATING` / `THINKING…` are two words for one state, and `WORKING — …` is a third used only during agent boot ("Waiting for agent…").

### 2.7 Cost (production + code)

### 2.9 Features with no users, and dead weight (production + code)

- **Scheduler**: 0 tasks, 0 runs. It cannot express "every Monday at 8"; "Every 7 days" emits `0 0 */7 * *` (measured with the shipped cron-parser from 2026-09-30: Oct 1, 8, 15, 22, 29, **Nov 1**, Nov 8); "Daily" means midnight and never says so; each run is a new `[Task]` chat (it does appear in the Chats list with the unread dot, but the run row has no link although the session id is stored); a run is a full default-model (Opus 5) high-effort turn with every tool and no cap; a run whose result is `is_error` completes green as "Finished". ## 3. What other platforms do, and what it means here

Full inventories with sources and dates are in the seven research reports. This section keeps the items that bear on a local, Claude-only tool builder for non-technical scientists. None of the products was used hands-on; claims the researchers flagged as unverified are not repeated here.

### 3.1 The direct competitor appeared in June: Claude Science — and the question it forces

Anthropic's Claude Science (public beta 2026-06-30; included in the $20 Pro plan; free Standard seats for verified PIs) is a desktop app that pairs Claude with a sandboxed local Python/R environment on the user's machine. Its interaction primitives are the ones this review keeps finding missing in Acabox:

- **Permission cards** that name exactly what is requested ("Access ‹folder›?", "Run Python code?", "Connect to ‹host›?"), scoped Once / This conversation / This project / Global, with a Settings → Permissions revoke list; credentials reach code only when Claude asks and the user approves.
- **Plan approval before code runs**, with approved steps ticked off as work finishes.
- **Every output is a versioned artifact with a five-tab provenance record** (Messages / Code / Execution Log / Environment / Review); "the Execution Log is the authoritative record of what ran."
- **A background reviewer** that checks claims against what actually ran (computed-when-nothing-ran, value contradicts file, step not completed), surfaced as cards under the message.
- **Comments pinned to a point on a figure**, batched with the next message; figures open beside the chat.
- **Compute monitor** per kernel and a **context-usage view**; sessions **pause and ask before spending extra usage**; "Waiting on you" notifications.
- Sixty-plus read-only scientific connectors with no keys; literature retrieval OA-first; SSH/Slurm remote jobs.

**Cost, side by side (list prices, as researched; confirm before quoting):** Acabox on the owner's own key ran ≈ $300/month for one heavy user with single chats of $100–160; Claude Pro is $20/month and includes Claude Science; verified PIs get Standard seats free; Julius is $20–45; Hex $36–75 per editor. A scientist's cheapest route to "Claude that runs my analysis in my folders" is now a subscription, not an API key. The plain Claude Desktop app with a filesystem MCP server — the zero-build way for a Pro-plan user to have Claude read local folders — was not evaluated and is the more likely incumbent on a scientist's Mac today.

**Why Acabox, then.** The review's material supports one answer and the owner should write it in their own words: Acabox is local-first with no cloud sandbox and no hosted dependency that can be shut down under the user (Opal, Mocha and Relay all closed in 2026); its output is a durable, shareable instrument on disk rather than a chat artifact; it holds credentials in a proxy the model never sees; it links chats to tools and chats to chats; and it bills to the user's own API account with no plan ceiling. Each of those is a real difference for a lab that keeps data on its own machines and wants a tool it can hand to a colleague. None of them is visible in the product today (section 2.3, privacy; section 2.10, sharing), and none excuses the trust gaps in section 2. Question 1 asks for the paragraph.

Acabox cannot and should not copy the cost model or the cloud pieces. But the UX primitives above are the bar a scientist will now compare against, and several are available through the Agent SDK Acabox already uses: `enableFileCheckpointing` + `rewindFiles()`, `canUseTool` (which also carries `AskUserQuestion`), `total_cost_usd`/`modelUsage` on every result, `maxBudgetUsd`, `interrupt()`, and `Settings.permissions.deny` path rules.

### 3.2 What every vibecoding platform converged on (Lovable, Bolt, v0, Replit, Base44, Emergent, Figma Make, Canva Code, Hostinger, Glide, Cursor, Cline, Devin…)

1. **Cost per message, shown after the fact, with a pause at a threshold.** Lovable shows credits per message on hover and a running tracker, and pauses a build crossing 20 credits with *Continue / Finish up*; Replit shows cost per checkpoint on hover and blocks at a usage limit; Figma Make shows real credits per prompt on hover. The platforms that show nothing (Manus, Bolt, Emergent, Base44 before Sept) are rated 1.6–2.8/5 with "slot machine" and "charged for the AI's own mistakes" as the dominant complaint. Mocha shut down in May citing "expensive unit economics from the AI tokens". Acabox has none of this, despite being the only product in the set where the user pays Anthropic directly and the exact number is free.
2. **A restore point before every change, that never loses anything.** Lovable (snapshot per change: preview, diff, "go to message", Revert, bookmarks; "Undo latest edit" and "Revert and resend"), Bolt (free timeline restore), v0 (restore creates a new version), Replit (checkpoint of files + packages + chat + optionally DB), Cursor/Cline/Windsurf/Copilot CLI (checkpoints with three restore flavours), Base44 (version history with compare-to-live; undoable restore of a restore). All separate code rollback from data rollback and say so. Glide users: "I wish there was an undo button."
3. **Point at the thing.** Lovable `S` select-element → chips in the composer, plus draw/annotate and pinned comments; Bolt batched visual edits free until Save; v0 design panel + annotations mode; Replit Edit (deterministic edits straight to source, no credits) + Draw; Figma Make point-and-edit; Canva click-to-retype. "Non-coders cannot name a component; clicking it is the interface."
4. **Plan before build, with questions that have buttons.** Lovable Plan (1 credit, versioned, highlight-to-revise), Bolt Plan ("Implement this plan"), Replit task list (Review/Revise/Build here/Build in background), Base44 conversational plan mode with clickable options and mockups, Cursor plan mode asks clarifying questions, Jules' critic reviews auto-approved plans. Base44's Discuss mode at ~0.3 of a build message and Cline's Plan mode ("cannot modify any files") are the cheap "talk before building" pattern.
5. **Free or cheap fixes for the agent's own errors**, and docs that teach "fix once or twice, then revert": Lovable 10 free fixes/day, v0 free fixes for unedited code, Bolt free security fixes, Base44 free auto-fixes on paid plans.
6. **Evidence, not assurance, for self-testing**: screenshots in chat (Lovable, v0), video replay with "Begin take over" (Replit), Emergent/Anything QA agents. The zero-cost cousin is capturing runtime errors on first load and offering a one-click fix.
7. **Long runs need a steering wheel**: follow-ups while working (Lovable), prompt queues (Bolt), Stop everywhere, "Finish up" (wrap up gracefully, pay only for completed work); Devin "avoids charging for waiting periods".
8. **Templates and remix beat blank prompts**: every platform has a gallery with Preview + Remix; Lovable shows three design directions before the first build; Bolt has a prompt library and "Enhance prompt".
9. **Secrets requested by name with a reason, write-only** (Lovable), pasted keys offered as connectors, connectors revocable centrally (Replit).
10. **Scheduled work reports into the chat that created it, with a per-run budget, and pauses after repeated failures** (Replit Routines, Base44 workflows, Deepnote, Notion credits "skip, never backfill").
11. **Memory announces itself and is vetoable** (Augment, Devin Knowledge suggestions); Dia retired memory entirely ("newer models no longer require it"); Raycast scopes it to projects with auto-summaries.

### 3.3 What the science and data tools do for trust

- **Review changes, not code**: Hex's Notebook Agent walks the user through a *pending-changes* modal with per-cell Confirm/Undo; Deepnote shows a before/after diff with "reject all" and saves an immutable snapshot of every run; Jupyter AI 3 and Positron ask before writing. Every notebook-editing agent shipped an approval surface in 2026; Acabox is the outlier.
- **Deterministic numbers, narrated by the model**: Tableau Pulse computes insights statistically and lets the LLM only write the sentence; Potato calculates volumes rather than generating them; Julius's reviews ("results differ when you ask twice", "parametric tests on non-normal data") show why a re-runnable artefact matters — and Julius then sunset its notebooks.
- **Provenance per claim**: Kosmos links every conclusion to code lines or passages and is graded 85% accurate on data statements but 58% on synthesised conclusions — the argument for labelling "computed from your data" vs "interpretation"; Elicit attaches a supporting quote and explanation to every extracted value; Consensus shows the quote on hover; Power BI shows "How Copilot arrived at this"; GlideOS lets users inspect how any figure was derived and "asks rather than guessing silently".
- **The non-AI bar is GraphPad Prism**: an assumptions checklist on every inferential result, effect sizes with CIs by default, linked data→result→figure updates, an export dialog with DPI, dimensions and colour space. No AI tool in the set matches it; all of it is deterministic.
- **Spreadsheet-first helpers, all zero-call**: Julius profiles a dropped file and offers three templated starter questions; Benchling runs a deterministic data-quality check on open; Julius lets the user "freeze" an analysis. Excel Copilot and Gemini in Sheets are the tools a bench scientist most likely already has open; coverage of them here is thin.
- **Domain packs as skills loaded per data type**: Latch (built with assay vendors, QC figures first), Biomni-E1 (150 tools, 59 databases), Edison Analysis (flow, RNA-seq). Acabox's ten database skills are the seed, and in production none has ever been used. Consensus, Scite and Elicit publish MCP endpoints; the Connectors catalog (Hex, Sentry, Notion, Linear, GitHub) is developer tools.
- **Published UX research that matters for this audience**: NN/G on the "articulation barrier" (users lack the vocabulary to prompt; pair the text box with pickers), on prompt controls and starters ("contextually relevant, personalized, and specific"), on new users ("ask the bot what it can do"; no long onboarding popups), and on buttons-and-checkboxes beating prose follow-ups; Jakob Nielsen's think-time rules (meaningful status text, ETAs with ranges, "since you were gone" recaps, outcome-first notifications); Kamushken's 2026 agent patterns (tiered permission gates by reversibility × error cost, "pause, not kill", diff-first summary, action trail with undo; anti-patterns: infinite spinner, fake progress, hidden autonomy); Yan (2026, 113 non-technical participants): user-written standing policies protect *less* than per-action approval — non-experts keep choosing "ask".

### 3.4 Where Acabox is ahead

Local files as first-class inputs with no upload; durable `tool-data` that survives deletion; host-owned jobs that survive restarts with honest states; a credential proxy the agent cannot see through; quote-with-provenance from any surface including inside tools; chat-to-chat links the agent can read; per-chat model pin with an explanation; on-device dictation; a two-probe API Test that tells the truth; a read-only share model with staleness detection and a provenance line; and the premise itself — nothing leaves the machine except what the model reads, and the product cannot be shut down under the user.

### 4.5 Deliberately not recommended

- **Keep-alive sessions so the agent's own pollers run.** CLAUDE.md's recorded decision; the one open-ended bill. The bounded host-side `wait_for` is a different thing (no session stays alive, zero calls while waiting) and is question 4, not a recommendation.
- **Removing the per-tool notebook file.** It is each tool's durable state store (`useAppState`) and works. The *kernel gateway* is a separate question: zero runs in nine weeks, but that user never did bench analysis; stop installing the kernel stack eagerly, fix `NotebookEdit`'s denial (C18), and decide after the 4.0 bench tasks (question 9).
- **Automatic retries of failed builds, automatic forwarding of runtime errors, autonomous post-build QA, "Verify this tool", three design directions, an automatic reviewer after every turn, session recaps, next-prompt suggestions, Haiku-written row summaries, a dictation "tidy" pass.** Each adds model calls per failure or per turn; the owner's rule calls that a regression. The manual, labelled button is the design; "Check this" (C31) is the only reviewer, opt-in and labelled on the button.
- **A plan-approval gate, editable plan files or a Plan/Discuss mode.** +1 turn per task; approved plans still yield wrong code (the "plan mode is dead" post-mortem); this audience cannot evaluate plan text. A six-line "here's what I'll build" in the agent's instructions rides the existing turn; the result-side gates are C02 and C12.
- **Per-action approval prompts, a Manual/Auto/Skip dial, or user-authored permission policies as the primary control.** 93% of prompts are approved (Anthropic 2026); non-experts choose "ask" at runtime and do not maintain policies (Yan 2026). Deterministic boundaries plus a single confirm class (C14).
- **Numeric confidence scores; generic disclaimers under every answer.** They raise agreement with wrong answers too (Whitmore 2026; Li 2025) and become clutter (NN/G).
- **Silently routing small edits to a cheaper model.** "Quality roulette" and a silent change to the pinned default; a visible per-message chip is acceptable later.
- **Building the same message on two models (Base44).** 2× cost.
- **Subscription sign-in.** Anthropic's policy forbids third-party use of Claude.ai/Pro/Max OAuth; API keys only — say so in Settings (C06).
- **Apple on-device Foundation Models for titles or previews.** Zero Claude calls but a non-Claude model; violates Claude-only.
- **A new memory-management UI.** Memory works (28 files loaded every turn); the field is dropping memory UIs (Dia retired it; Claude moved to a settings list); per-tool instructions (C35) are the better container.
- **Credit systems and "free fix" allowances.** Acabox bills nothing itself; cost visibility (C07) and the fix-loop guard (C12) are the honest analog.
- **A full ⌘K command palette; bundling Python now; a Redshift/DSN credential type; a starter gallery of verified tools; an element picker inside mini-apps; tool drafts/branches; jump-to-message from search.** Real but not week-one; each is M–L; several are recorded elsewhere as deferred. - **In-app browser, cloud routines, Dispatch, mobile remote control, computer use, deep-research mode, multiplayer, Figma import, custom domains per tool.** CLAUDE.md decisions, infrastructure a private local app does not have, or features of a hosted product.
